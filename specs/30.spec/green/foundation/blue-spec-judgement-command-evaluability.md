# 승격된 spec 의 판정 명령은 현 HEAD 에서 평가된다

> **위치**: 판정 대상 `specs/30.spec/blue/**/*.md` (HEAD=`c64c946` 실측 **69 파일**). 발화 채널 (**미부착 — §참고 §채널 부착**): `scripts/check-blue-judgement-evaluable.sh` + `package.json` `scripts.check:blue-judgement`. 기존 동류 채널 16건이 같은 규약을 따른다 (`scripts/check-*.sh` ↔ `check:*` — 예 `scripts/check-deps-coherence.sh`).
> **관련 요구사항**: REQ-20260831-060 FR-01~FR-07 · NFR-01~NFR-03 (출처: 운영자 결함 신고 — `RULE-05 §결함 신고`)
> **최종 업데이트**: 2026-08-31 (by inspector — REQ-20260831-060 흡수, HEAD=`c64c946`)

> 참조 코드는 **식별자 우선**. 라인 번호는 스냅샷 (HEAD=`c64c946`).

## 역할

승격된 계약이 자기 판정 명령을 잃어도 아무 신호가 나지 않는다. HEAD 실측: `30.spec/blue/**` 의 판정 명령 **78건(출현 88곳 / 69 파일 중 27 파일)** 이 `rc=2` 를 낸다. `rc=2` 는 grep 이 대상을 **열지 못했다**는 뜻이며 — 명제가 참인지 거짓인지가 아니라 **평가되지 않았다**는 뜻이다.

**방어 대상 (`RULE-07 §주제 우선순위 2` — 기존 자동 게이트가 검출하지 못하는 silent regression)**: `rc=2` 는 조용하다. 게이트 다수가 "0 hits 여야 한다" 형태라 `rc=1` 을 기대하는데, `rc=2` 도 "0 이 아닌 rc" 이므로 `! grep` 이나 `|| true` 로 감싸면 **통과로 읽힌다.** 파일이 사라진 것과 위반이 없는 것이 같은 신호가 된다. 실물: `components/log.md:172` 의 `bash -c 'grep -qF "Loading logs..." src/Log/LogList.jsx'` 는 파일이 없어 `rc=2` 이며, 부정 게이트 안에 들어가면 `!` 가 그것을 뒤집어 **`rc=0`(통과)** 으로 만든다. 위반이 없어서가 아니라 **볼 파일이 없어서** 통과한다.

**어느 기존 게이트도 이 방향을 재지 않는다.** `RULE-07 §promote 조건 2` 는 *"명령 부재·실행 불가가 1건이라도 있으면 promote 거부"* 를 요구하지만 그것은 **승격 시점**을 지킨다. 승격된 뒤 트리가 움직여 명령이 무효가 되는 경로는 어느 규약도 막지 않는다. `RULE-06 §게이트 실효 검증` 은 게이트 **도입 시점**의 민감도를, `§음성 대조` 는 정상 변형에서의 특이도를 잰다 — **둘 다 대상이 사라지는 방향은 재지 않는다.** 이 부류가 정확히 그 사이로 빠진다.

**기원은 단일 사건이고 그 뒤로 감지 없이 190 커밋이 지나갔다.** `src` 는 2026-08-29 `b793703` (*"테스트·픽스처 TypeScript 전환 — src 전체 TS 완료"*) 로 전면 전환됐고 현 HEAD 의 `src` 에 `.js`/`.jsx` 는 **0개**다. 그 전환 하나가 판정 명령 **54건(출현 60곳)** 을 한꺼번에 무효화했다. 무효화된 spec 들은 전환 이전에 마지막으로 손댔다 (`components/common.md` 는 2026-05-17). 그 뒤 190 커밋과 7 건의 promote 가 지나갔다.

**계약면은 경로가 아니라 평가 가능성이다.** `.js` → `.ts` 이관은 이 불변식을 만족시키는 **수단**이며, 수단을 계약으로 쓰면 다음 이관 때 같은 일이 반복된다.

의도적으로 하지 않는 것: **판정 명령이 내는 참/거짓** (본 계약은 `rc=0` 이냐 `rc=1` 이냐를 요구하지 않는다 — `rc=2` 가 아닐 것만 요구하며, 평가된 뒤의 위반은 각 spec 자신의 소관이다), `30.spec/green/**` (미승격 문서는 작성 중이며 자리표시자가 정당하다), `40.task/**` · `60.done/**` · `50.blocked/**` 의 명령 (감사 기록이며 재실행 대상이 아니다), `rules/`·`.claude/agents/` 문면 개정 (운영자 소관 — `RULE-01` writer 매트릭스), **timeout 명령의 실행 시간** (§참고 §미측정).

## 공개 인터페이스
- 신설 채널: `scripts/check-blue-judgement-evaluable.sh` — 인자 없음, 종료 코드로 판정 (`0` 충족 / `1` 위반). `package.json` 의 `scripts.check:blue-judgement` 로 발화한다. 저장소의 기존 `check:*` 16건과 같은 규약이다.
- 기존 인터페이스 변경 없음.

## 동작

1. **(I1) blue 의 판정 명령은 평가된다**: `30.spec/blue/**` 의 판정 명령을 현 HEAD 에서 실행하면 "대상을 열지 못함"(`rc=2`) 이 아닌 rc 를 낸다. 평가 **결과**가 참인지는 본 계약이 요구하지 않는다.

2. **(I2) 판정 명령 span 은 그대로 실행 가능한 문자열이다**: 인라인 코드 스팬 안에 자리표시자(`…` · `<자리표시자>`)나 기대 결과(`→ N hits`)가 섞이지 않는다. 섞이면 그 span 은 명령이 아니라 명령을 **설명하는 문장**이며, 실행하면 `rc=2` 를 낸다 (HEAD 실측 13건).

3. **(I3) 채널은 `rc=2` 를 `rc=1` 과 구별한다**: 단순히 "0 이 아님" 으로 묶으면 본 결함이 정확히 그 안에 숨는다. 분류는 최소 세 갈래다 — **충족**(`rc=0`) · **위반**(`rc=1`) · **무판정**(`rc=2`). 무판정만 본 계약의 위반이다.

   > **이 항목이 계약의 핵심이다.** `rc≠0` 으로 뭉뚱그린 채널은 결함 78건을 전부 "위반" 으로 보고하고, 그러면 각 spec 소관인 진짜 위반과 섞여 판별 불가가 된다. 반대로 `rc≠1` 로 뭉뚱그리면 무판정이 통과로 읽힌다 — 지금 상태 그대로다.

4. **(I4) 모집단은 도출한다**: 스캔 대상은 열거가 아니라 `find`/glob 으로 산출한다 (`RULE-06 §열거 고정 금지`) — 하드코딩하면 이후 추가된 spec 이 스캔 밖에 숨는다. 도출 결과가 **공집합이면 무판정 실패**한다. 빈 목록을 돌고 `rc=0` 을 내는 채널은 검출력이 0 이다.

5. **(I5) 산문 조각은 판정 대상이 아니다**: 피연산자 없는 플래그 언급(본문이 `grep -qF` 같은 표기를 **설명**한 자리)은 `grep` 이 사용법 오류로 `rc=2` 를 내므로 오탐이다 — HEAD 실측 고유 **10건 / 출현 31곳**. 제외 규칙과 그 근거 수치가 **채널 정의에 박제**된다. 규칙 없이 걸러 내면 다음 측정이 재현되지 않는다.

6. **(I6) 빈 추출은 실패다**: 추출이 빈 문자열을 낸 경우 실행하지 않고 실패로 판정한다 — `bash -c ""` 는 `rc=0` 이라 **미실행이 통과로 읽힌다** (`RULE-06 §추출 실패 검출`). 닫히지 않은 백틱 스팬이 이 경로이며, 여는 런과 **같은 길이의 닫는 런**까지를 한 스팬으로 보아야 한다.

7. **(I7) 채널은 읽기 전용이고 반드시 끝난다**: 판정 명령을 실제로 실행하므로 (a) 실행 전 쓰기·삭제 연산(`>` 리다이렉트 · `rm` · `mv` · `cp` · `sed -i`) 포함 여부를 선별해 포함된 명령은 **실행하지 않고 별도로 보고**하고, (b) 각 명령을 `stdin=/dev/null` 과 유한 타임아웃 아래 실행한다. **인자 없는 `grep` 은 stdin 을 기다려 매달린다** — 본 흡수의 측정이 실제로 겪었다.

   > `>/dev/null`·`2>&1` 은 쓰기가 아니다. 이 구분을 놓친 1차 선별이 80건을 통째로 제외해 `rc=2` 를 65건으로 **과소 보고**했다 (§스코프 규칙 §측정 방법 정정).

8. **(I8) 실행 전제는 판정 문면에 적힌다** (Should): 빌드 산출물(`build/**`) 참조처럼 전제가 필요한 명령은 그 전제를 문면에 명시한다. 전제가 적혀 있지 않으면 **평가 가능한 명령이 결함으로 오분류**된다 — 빌드 전 `rc=2` 이던 8건 중 7건이 `npm run build` 후 `rc=0`/`rc=1` 로 평가됐다.

9. **(I9) 판정은 결정적이다**: 같은 HEAD·같은 전제에서 두 번 실행하면 같은 분류를 낸다. 격리 사본과 저장소 루트의 차이는 gitignored 경로·빌드 산출물로 전부 귀속되어야 한다.

### 회귀 중점
- **`rc≠0` 으로 뭉뚱그린 채널은 (I3) 을 깬다.** 78건이 각 spec 소관의 진짜 위반과 섞여, 채널이 붉기만 하고 무엇이 문제인지 말하지 못한다.
- **모집단을 열거로 고정하면 (I4) 를 깬다.** 오늘 69 파일이 맞아도 다음 spec 이 스캔 밖에 숨는다. 이 저장소는 하드코딩된 5개 스크립트 목록이 이후 추가된 6개를 숨긴 실측을 이미 갖고 있다 (`RULE-06 §열거 고정 금지`).
- **닫히지 않은 백틱을 빈 문자열로 넘기면 (I6) 을 깬다.** `bash -c ""` 가 `rc=0` 이라 미실행이 충족으로 계수된다 — 채널 자신이 겨누는 결함과 **같은 부류**의 결함이다.
- **`>/dev/null` 을 쓰기로 오인하면 (I7) 을 만족시키면서 (I1) 의 계수를 과소 보고한다.** 본 흡수가 실제로 겪었고 정정했다.
- **경로 이관 자체를 계약으로 삼는 방향은 다음 이관에서 되풀이된다.** 계약면은 평가 가능성이지 확장자가 아니다.
