## 역할

게이트의 실패 보고는 **측정 층·분기와 무관하게 대칭**이다 — 같은 실패 조건은 같은 등급(종료 코드)으로 보고되고, 하위 프로세스를 구동한 분기는 실패 시 동등한 증거(종료 코드 + 출력)를 남긴다.

**방어 대상 (RULE-07 §주제 우선순위 2 — 명시 의무).** 본 계약이 방어하는 손상은 두 가지이며, 둘 다 기존 자동 게이트로 검출되지 않는다.

1. **"측정 실패" 가 "계약 위반" 으로 오분류된다.** 게이트는 전수 1회 + 샤드 N회를 구동하고, 현 HEAD 의 샤드 키는 **12개**다 (`:255-268` 도출 규칙). 샤드 개별 성공률 `p` 에 대해 게이트 성공률은 `p^12` 이므로 **실행 실패는 단조성 위반보다 12배 자주 발화한다.** 그 12배가 전부 `exit 1`(계약 위반)로 나오면 게이트가 잡으라고 만들어진 진짜 위반 신호가 실행 잡음에 묻힌다. 샤드 수는 디렉터리 추가마다 늘어나므로 이 비대칭은 **단조 악화**한다.
2. **실패 원인을 CI 로그만으로 판별할 수 없다.** 산출물 부재는 "하위 vitest 가 하드 실패했다" 는 사실 판정이고 그 원인은 teardown / timeout·DNS / 실제 FAIL 중 하나인데, 그 분기가 종료 코드와 출력을 **버린다.**

**이것은 새 정책이 아니라 이미 선언된 계약의 복원이다.** 스크립트 헤더가 스스로 등급 체계를 선언해 뒀고(`:17-23`), 저장소는 같은 원칙으로 이미 두 번 분리를 수행했다 — 공허 산출물 → `exit 3` (`:20-22`), 완전성 단언 붕괴 → `exit 4` (`:23`, `:330`·`:357`·`:437`·`:441`). "성격이 다른 실패는 다른 코드" 는 이 스크립트에 **확립된 규범**이며, 샤드 층 실행 실패만 그 규범 밖에 남아 있다.

의도적으로 하지 않는 것:
- (i) **판정 완화 금지** — 하향·allowlist·threshold 완화·실패 무시는 본 계약의 수단이 아니다. 필요한 것은 판정 완화가 아니라 **실패 분류**다. 분류 도입 후에도 실패는 여전히 실패다 (G-4).
- (ii) 샤드 flake 의 근본 원인 제거 — 별 축.
- (iii) **집계 위상 변경** — "샤드 1개 실행 실패 = 게이트 전체 실패" 를 유지할지(재시도·격리 정책)는 열린 설계 선택이며 불변식이 아니다. 또한 본 계약의 **후행 항목**이다: 존재하지 않는 실패 등급에 대한 채널 정책은 정의할 수 없다.
- (iv) 다른 `check:*` 스크립트로의 일괄 확장 — 본 계약은 위 스크립트 1개를 대상으로 한다.
- (v) 종료 코드의 **구체 숫자 배정** — 헤더 선언이 정의이며, 선언과 본문이 일치하는지만 판정한다.

## 동작

1. **(G-1) 층 간 등급 대칭** — 하위 프로세스 산출물 부재(`coverage-final.json` 미생성)는 **측정 실패**로 분류되며, 전수 층과 샤드 층이 **같은 종료 코드**를 낸다.
   - **HEAD=`8da63f6` 실측: 위반.** 전수 층 `:306-308` 은 `exit 2` 로 선언대로 나가지만, 샤드 층 `:403-406` 은 `FAILED=1` 로만 표시하고 `:451-453` 이 일괄 `exit 1` 을 낸다.
   - `:452` 의 종료 메시지가 이 혼입을 문장으로 자백한다 — `"[FAIL] check:coverage-attribution — 위 샤드에서 단조성/실행 사실 판정이 실패했다"`. 두 성격을 `/` 로 이어 붙인 것이 곧 **등급이 합쳐졌다**는 뜻이다.
2. **(G-2) 등급 간 구분** — 계약 위반(소실 슬롯 ≥ 1)과 측정 실패는 서로 다른 종료 코드를 낸다. 한 실행에서 둘이 동시에 발생하면 우선순위를 헤더에 선언하고 그대로 따른다.
   - **HEAD 실측: 샤드 층이 세 등급을 하나로 접는다.** `:415-417` 은 `judge` 의 `JRC != 0` 을 무조건 `FAILED=1` 로 접으며, `judge` 는 단조성 위반(`1`)과 공허 산출물(`3`)을 구분해 반환한다 (`:80` `process.exit(code)`). 여기에 `:406` 의 측정 실패까지 합쳐져 **{측정 실패, 공허, 단조성 위반} → `exit 1`** 이 된다. 전수 층은 같은 세 등급을 `2`/`3`(`:320` `exit "$PRE_RC"`)/`1` 로 구분해 낸다 — 층 간 비대칭이 G-1 의 1건에 그치지 않는다.
3. **(G-3) 분기 간 증거 대칭** — 샤드 루프에서 하위 vitest 를 구동한 뒤 실패로 `continue` 하는 **모든 분기**는 해당 샤드의 종료 코드(`SRC_RC`)를 stderr 에 남기고, vitest 출력의 말미를 고정 상한 라인 수로 남긴다.
   - `SOUT`(stdout+stderr 전량)과 `SRC_RC`는 `:363-368` 에서 **이미 확보되어 있다.** 증거는 수집돼 있고 대부분의 분기가 그것을 버린다.
   - **HEAD=`8da63f6` 실측 (5 분기 중 `SRC_RC` 보존 1건):**

     | 분기 | 조건 | `SRC_RC` | 출력 덤프 |
     |---|---|---|---|
     | `:371-376` | 수집 0 (`No test files found`) | 없음 | `tail -10 >&2` |
     | `:381-385` | 요약 행 미검출 | **있음** (`rc=$SRC_RC`) | `tail -10 >&2` |
     | `:392-395` | 통과 테스트 0 | 없음 | 요약 행만 |
     | `:398-401` | 수집 파일 수 != 열거 | 없음 | 수치만 |
     | `:403-406` | **`coverage-final.json` 미생성** | 없음 | **없음** |
   - **가장 심각한 실패(하위 프로세스 하드 실패)에 증거가 가장 적다.** 바로 위 `:382` 분기는 `rc=$SRC_RC` 를 메시지에 박아 넣기까지 한다 — **판단은 이미 내려져 있었고 옆 분기로 전파되지 않았다.** 이것이 본 계약을 "개선 제안" 이 아니라 **대칭성 복원**으로 두는 근거다.
4. **(G-4) 정상 경로 불변** — 분류·증거 도입은 정상 트리의 판정 결과를 바꾸지 않는다. 위반 0 인 트리에서 게이트는 `rc=0` 이다.
5. **(G-5) 선언·구현 정합** — 본문은 헤더가 선언하지 않은 종료 코드로 종료하지 않는다.
   - **HEAD 실측: 충족** — 본문 리터럴 `exit` 인자 집합은 `{0, 1, 2, 4}` 이고 선언 집합 `{0,1,2,3,4}` 의 부분집합이다. `3` 은 동적 경로(`:320` `exit "$PRE_RC"`, `:219` `exit $?`)로만 발화한다.
   - **따라서 G-5 는 현 HEAD 에서 이미 참이다.** 단독으로는 `RULE-07 §반려 시그널` 의 중복·자명 명제에 가깝다. 본 계약이 G-5 를 두는 이유는 **G-1·G-2 를 충족시키는 변경이 새 코드를 도입할 때 선언 갱신을 함께 요구하기 위해서**다 — 즉 G-5 는 독립 목표가 아니라 G-1/G-2 변경에 붙는 **동반 조건**이다.
6. **(G-6) 채널 경계 보존** — 종료 코드가 소비 채널(`package.json:31` → `ci.yml:92`) 경계를 넘어 보존된다. 채널이 측정 실패와 계약 위반을 구분해 다룰 수 있는 정보를 받는다.

## 회귀 중점

1. (R-1) 새 실패 분기가 증거 없이 추가됨 — G-3 이 "구동 후 실패 `continue` 전 분기" 를 대상으로 하므로 신규 분기도 자동 포함된다. **분기 목록을 하드코딩하면 이 성질이 사라진다** (`RULE-06 §열거 고정 금지`).
2. (R-2) 등급이 다시 접힘 — `FAILED=1` 단일 플래그로 여러 등급을 모으는 구조가 유지되는 한 재발이 쉽다. 등급별 플래그·변수로 분리되지 않으면 G-1/G-2 는 국소 패치로 끝난다.
3. (R-3) 판정 완화로의 오회복 — 실패가 잦다는 이유로 실패를 무시·재시도로 흡수하는 변경. §역할 (i) 가 명시 배제하며 G-4 는 정상 경로만 고정하므로 **완화를 막지 못한다** — 이 축은 §미측정·비판정 항목으로 남는다.
4. (R-4) 로그 폭주 — 증거 덤프에 상한이 없으면 CI 로그를 삼킨다. G-3 이 고정 상한을 요구한다.

### 미측정·비판정 항목

- **집계 위상 결정** — "샤드 1개 실행 실패 = 게이트 전체 실패" 유지 여부(재시도·격리 정책)는 불변식이 아니라 열린 설계 선택이며, 현 HEAD 에서 명령 1회로 rc 판정할 수 있는 명제가 아니다. 또한 G-1/G-2 착지의 **후행 항목**이다 — 존재하지 않는 등급에 대한 채널 정책은 정의할 수 없다.
- **`p^12` 성공률 목표치.** `p ≥ x` 형태의 목표는 측정 채널이 없어 체크박스로 두지 않는다. `p^12` 은 요구사항이 아니라 등급 분리의 **비용 근거**다.
- **NFR-01 (임의 샤드 실패 1건의 3축 판별 가능성).** 실패가 발생해야 판정되는 '미래 사건 대기' 부류다. G-3 이 요구하는 증거(종료 코드 + 출력 말미)가 판별의 **필요 조건**이며, 충분성은 실제 실패 로그로만 확인된다. 그 확인은 §발화 채널 (Dir-2) 주입이 대신한다.
- **판정 완화로의 오회복 방지 (R-3).** "완화하지 않았다" 는 부정 명제라 단일 명령으로 판정되지 않는다. 방어는 게이트가 아니라 §역할 (i) 의 명시 배제와 리뷰에 의존한다.
- **본 계약의 다른 `check:*` 로의 확장.** 같은 대칭성이 다른 스크립트에도 성립하는지는 별 축이며, 대상 스크립트별 실측 없이 일반화하지 않는다.
