# 측정 결과는 그것이 읽은 트리에 귀속 가능하다

> **위치**: 측정 채널 전반 — 계약 식별자 `package.json scripts.check:measurement-tree-attribution` (HEAD=`5b2ed3b` 미부착). 부재 증명 열거는 §동작 (M-2).
> **관련 요구사항**: REQ-20260825-026
> **최종 업데이트**: 2026-08-25 (by inspector — tick 225 최초 등록)

## 역할

`rc=0` 은 **어떤 트리에서 났는가** 와 함께여야 증거가 된다. 측정 명령의 실행 구간 동안 워킹트리가 변하면 그 `rc` 는 **존재하지 않는 트리의 rc** 이며, 본 계약은 그 사실이 조용히 지나가지 않도록 요구한다.

핵심 명제 — **판정 결과와 판정 유효성은 서로 다른 사건이다.** 게이트가 위반을 못 찾은 것과 그 게이트의 측정을 믿을 수 없는 것은 다르며, 둘을 같은 `rc=0` 으로 표현하면 후자가 전자로 흡수된다.

의도적으로 하지 **않는** 것:
- (i) **에이전트 간 동시 실행 조정·복원 권한·writer 규율을 다루지 않는다.** 그 축의 수리 표면은 `rules/**` · `.claude/agents/**` 이며 `RULE-01 §쓰기 권한` 상 **operator 전용**이라 파이프라인 안에서 닫히지 않는다 (§참고 §운영자 귀속 — 원문 보존).
- (ii) **작업 손실 방지·자동 백업을 다루지 않는다.** 같은 이유다.
- (iii) **파일 잠금·트랜잭션·배타 제어를 도입하지 않는다.**
- (iv) **측정 구간 밖의 편집을 차단하지 않는다.** 측정 종료 후 커밋 전의 편집은 정상 작업 흐름이다.
- (v) **지문의 산출 방식을 단일 지정하지 않는다.** 계약하는 것은 수단이 아니라 **귀속 가능성과 fail-closed 발화**다. 계약이 고정하는 유일한 표면은 발화 채널 식별자다 (§발화 채널).

> **본 계약이 취한 것은 완화 축 하나다.** 작업 파괴 자체는 막지 못한다. 막는 것은 **파괴된 트리의 rc 가 증거로 승격되는 것**이다.

## 공개 인터페이스

- 발화 채널 식별자: `check:measurement-tree-attribution` (`package.json scripts`).
- 산출: 트리 지문 + 판정 category 토큰. 지문은 **파일 내용을 반영**하며 이름 목록이 아니다.
- 종료 코드 3분할: `0` 유효·정합 / `1` 위반 / `2` **무효(invalid measurement)** — 후자 둘은 반드시 구분된다.
- 지문 산출은 **read-only**. 워킹트리·인덱스·stash 를 변경하지 않는다 (`git stash` 류 금지 — 그 자체가 본 계약이 겨누는 사고 부류다).

## 동작

### (M-1) 이 축의 위반은 red 를 만들지 않고 green 을 만든다

파이프라인의 모든 승격·완료 판정이 "명령을 실행했고 `rc=0` 이었다" 에 의존한다 — `RULE-07 §promote 조건 2` 는 promote 직전 전수 재실행을 요구하고, `RULE-06 §게이트 실효 검증` 은 주입 왕복의 rc 를 요구한다. **그 rc 가 커밋되는 트리와 무관할 수 있다면 두 규약이 요구하는 증거의 의미가 정의되지 않는다.**

방어 대상은 **DoD 근거의 위조 — 악의가 아니라 사고로 발생하는 부류**다 (`RULE-07 §주제 우선순위` 축 2 가 요구하는 명시).

### (M-2) 현 HEAD 에 이 축을 재는 채널이 없다 — 부재 증명은 열거로 세운다

`0 hit` 이 아니라 **호출 지점 전수 열거**로 확인했다 (tick 225 재확인).

| 위치 | 호출 | 읽는 것 |
|---|---|---|
| `check-commit-writer-coherence.sh:56,63,151,158` | `git log` / `git rev-parse` | 커밋 이력 |
| `check-env-api-base-presence.sh:97,99` | `git ls-files` | 인덱스의 **이름 목록** |
| `.husky/pre-commit:5,11,17,25,34,43,52,63` | `git diff --cached --name-only --diff-filter=ACMR` | 스테이지된 **이름 목록** (트리거 조건) |

이상이 `scripts/*.sh`(`pipeline-health.sh` 제외)와 `.husky/**` 의 `git` 호출 **전부**이며, **파일 내용도 측정 구간 중의 변이도 읽는 것이 하나도 없다.** `tsc` · `eslint` · `vitest` 도 같다 — 실행 시점에 읽은 내용으로 판정할 뿐, 그 내용이 판정 직후 바뀌었는지는 관측 대상이 아니다.

### (M-3) 지문은 이름이 아니라 내용을 반영해야 한다

관측된 사고에서 **스크립트는 이름을 유지한 채 내용이 HEAD 상태로 되돌아갔다.** 이름 목록 기반 지문은 이 변이에 대해 완전히 침묵한다. 따라서 지문은 **추적 파일의 내용**과 **미추적 파일의 존재**를 함께 반영한다 — 실제로 소실된 것은 후자 부류(픽스처 3파일)였다.

### (M-4) 검출 채널이 우연에 의존하고 있었다

관측된 두 건 모두 **게이트가 아니라 사람이** 잡았다 — 한쪽은 ack 라인의 도출 수치가 baseline `seam=3` 이어야 하는데 `seam=4` 로 나와서, 다른 쪽은 커밋 시도가 `nothing to commit, working tree clean` 이라서다.

즉 **수치를 발화하는 습관이 유일한 검출 채널이었다.** 그 습관은 게이트마다 제각각이고 규약이 요구하지 않으며, **발화하는 수치가 우연히 변한 것과 상관있을 때만** 작동한다. 우연에 의존하는 검출은 계약이 아니다.

### (M-5) 동시 실행은 원인의 한 사례일 뿐이다 — 순차 전환으로 축이 소멸하지 않는다

에디터 자동 저장 · watch 모드 재생성 · 장시간 측정 중 수동 편집 · 백그라운드 포맷터가 모두 같은 결과를 낸다. **본 계약은 동시 실행이 0 이어도 유효하다.** 운영자의 순차 실행 전환은 파이프라인 밖 조치이므로 본 계약의 판정 대상이 아니며, 그 전환을 이유로 본 계약을 시점 귀속 항목으로 강등하지 않는다 (`RULE-07 §양성 기준` 시점 비의존성).

## 수용 기준

> 전 항목 명령 1회로 rc 판정 가능 (`RULE-07 §수용 기준 문장 규약`). 명령은 `package.json` · `scripts/**` · git 상태만 참조하며 **spec 경로를 어느 것도 참조하지 않는다** (`§promote 조건 2`). **HEAD=`5b2ed3b` (tick 225 등록) 기준 0/4.**
>
> **req 판본의 `scripts/<지문 스크립트>.sh` 자리표시자는 그대로 쓰지 않았다** — 실행 불가능한 문자열은 "명령 1회로 rc 판정 가능" 을 충족하지 못한다. 수단 중립을 유지하면서 실행 가능하게 만들기 위해, 계약을 **스크립트 파일명이 아니라 npm 채널 식별자**에 건다. 파일명·구현 형태는 여전히 자유다.

- [ ] (Must, M-6) 채널 실재 — 판정: `bash -c 'grep -qE "\"check:measurement-tree-attribution\"[[:space:]]*:" package.json && npm run --silent check:measurement-tree-attribution >/dev/null 2>&1'` → **rc=0**. **HEAD=`5b2ed3b` (tick 225) 실측 rc=1 (식별자 부재) → 미충족.** 두 조건의 논리곱인 이유 — 식별자만 재면 `"check:...": "true"` 같은 빈 껍데기가 통과하고, 실행만 재면 식별자 오타가 `npm ERR!` 를 내며 rc≠0 이 되어 원인이 뭉개진다.
- [ ] (Must, M-7) 지문 산출이 read-only 다 — 실행 전후 `git status --porcelain` 이 **바이트 동일**. 판정: `bash -c 'a=$(git status --porcelain); npm run --silent check:measurement-tree-attribution >/dev/null 2>&1; rc=$?; b=$(git status --porcelain); [ "$a" = "$b" ] || { echo "tree mutated by the probe itself" >&2; exit 1; }; exit $rc'` → **rc=0**. **HEAD=`5b2ed3b` (tick 225) 실측 rc=1 → 미충족.** **이 항목이 자기 자신을 겨눈다는 점이 요점이다** — 트리 무결성을 재는 도구가 트리를 바꾸면 그 도구는 본 계약이 겨누는 사고의 원인 부류가 된다 (§공개 인터페이스 `git stash` 금지).
- [ ] (Must, M-8) 판정 모집단 seam 보유 — 자기 민감도를 저장소 무변경으로 검증할 수 있어야 한다. 판정: `bash -c 'f=$(grep -rlE "measurement-tree-attribution|tree-attribution" scripts/ 2>/dev/null | head -1); [ -n "$f" ] || { echo "derive=0 script absent" >&2; exit 2; }; grep -qE '"'"'^[A-Z_]*(ROOT|GLOB|FILES)="\$\{[A-Z_]+:-'"'"' "$f"'` → **rc=0**. **HEAD=`5b2ed3b` (tick 225) 실측 rc=2 (스크립트 부재 — 무판정) → 미충족.** **공허 통과 가드 내장** — 스크립트가 없으면 `exit 2` 로, 부재를 충족으로 읽지 않는다. seam 형태는 slug `foundation/gate-judgement-population-injectable-seam` §공개 인터페이스와 동일 계약이다.
- [ ] (Must, M-9) 무효와 위반이 구분 발화된다 — 지문 산출 불가 상황(git 저장소 아닌 경로를 seam 으로 주입)에서 **`rc=2`** 를 내며, 이는 위반의 `rc=1` 과 다르다. 판정: `bash -c 'r=$(grep -rlE "measurement-tree-attribution|tree-attribution" scripts/ 2>/dev/null | head -1); [ -n "$r" ] || { echo "script absent" >&2; exit 2; }; v=$(grep -oE '"'"'^[A-Z_]*(ROOT|GLOB|FILES)(?==)'"'"' "$r" 2>/dev/null | head -1); d=$(mktemp -d); out=$(env $(grep -oE "[A-Z_]+_(ROOT|GLOB|FILES)" "$r" | head -1)="$d" bash "$r" 2>&1); rc=$?; rm -rf "$d"; echo "$out"; [ "$rc" -eq 2 ]'` → **rc=0**. **HEAD=`5b2ed3b` (tick 225) 실측 rc=2 (스크립트 부재) → 미충족.** **fail-closed 요구** — 지문 산출 실패(저장소 밖 · 권한 오류)를 성공으로 읽지 않는다. `rc=1` 과 `rc=2` 를 합치면 "게이트가 위반을 찾았다" 와 "이 측정은 믿을 수 없다" 가 같은 사건이 되고, §역할 핵심 명제가 무너진다.

## 참고

### 게이트 실효 검증 이관 (RULE-07 §처리 · RULE-06 §게이트 실효 검증)

아래는 **'가정 주입 요구' 부류**라 체크박스로 두지 않으며, 검출 방향을 보존한 채 **수리 task 의 `## 검증/DoD`** 로 이관한다. developer 는 `RULE-04` notes 에 `injection: N/N detect` 를 박제한다. **이관처 task 가 발행되기 전까지 귀속처는 본 절의 명시적 지시다** (이관처 없는 강등 금지).

- **(Dir-1) 내용 변경 — 관측된 사고의 형태** — 측정 구간 중 추적 파일 1건을 **이름 유지 · 내용 변경**으로 수정 → 지문 불일치 → `rc≠0` → 원복 → `rc=0`. **이름 목록 기반 지문은 이 방향을 통과한다** (§동작 (M-3)) — 그래서 이 방향이 설계 선택을 실제로 판별한다.
- **(Dir-2) 미추적 파일 소실** — 측정 구간 중 미추적 파일 1건(픽스처 류)을 삭제 → 지문 불일치 → `rc≠0` → 원복 → `rc=0`. 관측된 사고에서 실제로 사라진 것이 이 부류다.
- **(Dir-3) 특이도** — 아무것도 건드리지 않은 구간에서 `rc=0`. 이 방향이 없으면 **"항상 무효를 내는" 게이트가 (Dir-1)(Dir-2) 를 통과한다.**
- **(Dir-4) fail-closed** — 지문 산출을 불가능하게 만들고 `rc=2` 확인. (M-9) 의 주입 판본이다.
- **(Dir-5) 오탐 — 측정 자신이 만드는 파일** — 빌드 산출물·커버리지 출력이 생기는 측정을 감싼 상태에서 `rc=0`. 이 방향이 없으면 제외 규칙 부재가 (Dir-3) 을 통과한다.

### 운영자 귀속 (본 계약 밖 — 원문 보존)

followup `2230` §기대 3항은 **본 계약에 포함되지 않는다.** 수리 표면이 `rules/**` · `.claude/agents/**` 이고 두 경로 모두 `RULE-01 §쓰기 권한` 상 operator 전용이라, inspector 도 developer 도 쓸 수 없다. 감사성을 위해 원문을 보존한다.

> 1. 복원은 자신이 만든 변경분에 한정한다 (경로 단위 blind revert 금지).
> 2. 복원 전 대상 경로에 타 writer 의 미커밋 변경이 있는지 확인하고, 있으면 복원을 포기하고 `50.blocked/pipeline/` 에 박제한다.
> 3. 프로토타이핑은 `git worktree` 밖으로 새지 않도록 격리하고, 누출 시 복원이 아니라 신고 경로를 탄다.

함께 지적된 규약 공백 — *"`RULE-02 §금지` 가 막는 것은 자기 파괴이고 **타 에이전트 작업 파괴는 문면에 없다**"* — 도 같은 이유로 본 계약의 대상이 아니며 **운영자 판단 사항으로 여기 박제만 한다.**
