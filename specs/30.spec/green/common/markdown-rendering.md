## 역할

글쓴이가 쓴 것이 독자에게 그대로 보인다. **의도하지 않은 마크업이 글자를 삼키지 않고, 의도한 마크업이 글자로 남지 않는다.**

**방어 대상**: 파서가 조용히 내용을 바꾸는 회귀. 이 축의 실패는 게이트가 아니라 **독자가 먼저 본다** — 그리고 글쓴이는 자기 원문에서 잘못을 찾을 수 없다.

## 동작 — 블록

1. **ATX 제목의 닫는 `#` 은 내용이 아니다.** 줄 끝 `#` 런 앞에 공백이 있으면 닫는 시퀀스이며 개수는 여는 쪽과 무관하다. 앞에 공백이 없으면 내용이다 (`## C# 과 F#`). `####### 일곱` 과 `##제목` 은 여전히 문단이다.

2. **밑줄식 제목**: 문단 줄 바로 다음 줄이 `-` 만이면 `<h2>`, `=` 만이면 `<h1>` 이고 밑줄 줄은 남지 않는다. **바로 앞 한 줄만** 올라간다. 앞에 문단이 없으면 `<hr />` 이고, `*`·`_` 는 밑줄이 아니며, `- 항목\n---` 는 목록 + 가로줄이다.

3. **인용은 한 덩어리다.** 연속한 `>` 줄은 `<blockquote>` 하나이며 빈 줄에서 끊긴다. 인용 **안에서 블록 문법이 동작한다** — 목록·ATX 제목·밑줄식 제목·중첩 인용·**펜스 코드 블록** (`` > ``` `` 줄로 열고 닫은 블록 → `blockquote > pre`, 펜스 표기는 글자로 남지 않는다). 인용 내용의 인라인은 **한 번만** 처리된다.

4. **목록 항목의 내용은 마커 바로 뒤부터 시작한다.** 마커는 `-␣` 또는 `숫자.␣` 이며 그 전부가 표기다. 같은 내용을 두 표기로 쓰면 `<li>` 안 문자열이 같다.

5. **마커 없는 다음 줄은 그 항목의 내용이다** — 들여쓰기 유무와 무관하다. 목록은 끊기지 않고 **번호는 되감기지 않는다.** 들여쓰기로 쓴 공백·탭은 본문 앞에 남지 않는다. 열린 항목이 없는 들여쓴 줄은 그대로 문단이다 (`  hello` → `<p>  hello</p>`).

6. **빈 줄은 같은 종류의 목록을 끊지 않는다.** 산출이 그 줄을 걷어낸 입력과 문자열로 같다. 빈 줄 판정은 **공백·탭만 있는 줄을 포함**하며 그 술어는 파서 안에 하나뿐이다. 빈 줄 뒤가 목록이 아니거나 종류가 다르면 목록은 끝난다 — **단 내용 열까지 들여쓴 블록은 예외다 (19).**

7. **종류가 달라도 중첩된다.** 더 깊게 들여쓴 마커는 종류와 무관하게 그 항목 안에 중첩되고 바깥 목록의 여는 태그는 1개다. **같은 종류 중첩의 현 산출은 불변이다** — 종류 판정을 통째로 없애는 구현이 여기서 갈린다.

8. **파이프 표는 표로 렌더된다.**

9. **코드 블록 안의 마크다운은 파싱되지 않는다.** 들여쓰기·빈 줄·탭이 보존되고 HTML 은 이스케이프된다. 목록 항목 안에서 보존되는 것은 **내용 열 너머의** 들여쓰기다 — 내용 열까지는 항목의 표기다 (19).

### 블록 — 2026-10-13 흡수

19. **목록 항목의 내용 열까지 들여쓴 블록은 그 항목 안에 있다.** 내용 열은 마커 폭 + 뒤따르는 공백 수다 (`- `→2 · `1. `→3 · `10. `→4). 열린 항목의 내용 열 이상으로 들여쓴 펜스 코드 블록과 마커 없는 문단 줄은 **앞에 빈 줄이 있든 없든** 그 항목의 내용이고(`li` 의 자손), 그 뒤 같은 깊이·같은 종류 마커는 **같은 목록을 잇는다** — 여는 태그 1개, 번호는 되감기지 않는다. 항목 안 코드 블록의 각 줄에서 내용 열까지의 들여쓰기는 걷힌다. 빈 줄 뒤 블록이 내용 열 **미만**이면 목록은 끝난다 — `1. 첫째\n\n본문` 은 `<ol><li>첫째</li></ol><p></p><p>본문</p>` 그대로다. 내용 열 판정은 파서 안에 하나다.
    - 예: `1. 설치\n\n   ```\n   npm i\n   ```\n2. 실행` → `ol` 1 · `li` 2 · `pre` 는 첫 `li` 의 자손이고 `textContent` 가 `npm i` 로 시작한다. 빈 줄을 뺀 변형도 같다. `- 첫 문단\n\n  둘째 문단\n- 다음 항목` → `ul` 1 · `li` 2 · `둘째` 앞에 공백이 남지 않는다. `10. 열\n\n    본문\n11. 열하나` → `ol` 1 · `li` 2.
    - **마커 줄의 중첩 깊이(7)는 현 모델을 유지한다.** 내용 열은 마커 없는 블록의 귀속에만 쓴다. 두 판정을 하나로 합치면 `1. a\n  - b` (공백 2 < 내용 열 3) 처럼 지금 중첩되는 입력의 산출이 바뀐다.

20. **번호 목록은 글쓴이가 쓴 첫 번호부터 보인다.** 첫 항목 번호 N 이 1 이 아니면 정제를 거친 DOM 에서 그 `ol` 의 `start` 가 N 이다 (10진 정규화 — `003.` → `3`, `0.` → `0`). 첫 번호가 1 이면 `start` 를 내지 않는다 — `1. 하나\n2. 둘` 의 산출은 `<ol><li>하나</li><li>둘</li></ol>` 그대로다. 둘째 항목 이후의 번호는 매김에 영향이 없다 (`3. a\n7. b` → `start` 3, 항목 2). 중첩 번호 목록도 자기 첫 번호를 따른다. `start` 값은 숫자 문자만 담는다. 정제 쪽 조건은 `sanitizeHtml` (I15) 가 진다 — **한쪽만 고치면 독자에게는 아무 변화가 없다** (18).

21. **펜스 코드 블록은 여는 펜스의 문자·길이로 닫히고, 펜스 줄의 글자를 삼키지 않는다.** 펜스는 백틱 또는 물결 **3개 이상**이고 0~3칸 들여쓸 수 있다 (4칸 이상이면 펜스가 아니다). 닫는 펜스는 여는 펜스와 **같은 문자**이고 **개수가 같거나 많다** — 그보다 짧거나 다른 문자의 펜스 줄은 코드 내용으로 보인다. 여는 펜스가 N칸 들여쓰여 있으면 내용 각 줄에서 최대 N칸 걷힌다. 물결 펜스의 언어 표기와 하이라이트는 백틱 펜스와 같다 (`~~~kotlin` 의 산출 ≡ `` ```kotlin `` 의 산출). 펜스 판정은 파서 안에 하나이고 인용(3)·목록 항목(19) 안에서도 같은 판정을 부른다.
    - **펜스가 아닌 줄**: 백틱 펜스의 정보 문자열에 백틱이 있으면 그 줄은 문단이다 — `` ```인라인``` 문장\n다음 줄 `` → `pre` 0 · `code` 1(`인라인`) · `문장` 과 `다음 줄` 이 보인다. 물결 펜스는 정보 문자열이 비었거나 **언어 이름 꼴**(ASCII 영문으로 시작, 공백 없음)일 때만 펜스다 — `~~~ 그렇구나\n다음 줄` 은 문단이고 두 줄의 글자가 모두 보인다.
    - **CommonMark 와 갈리는 지점이다.** 표준은 물결 펜스의 정보 문자열을 제한하지 않는다. 그런데 정보 문자열은 화면에 나가지 않으므로, 표준대로면 한국어 늘임 표기(`~~~`)로 시작하는 산문 줄이 통째로 사라지고 닫는 펜스가 없으면 문서 끝까지가 코드가 된다. 줄 가운데의 `아~~~ 그렇구나` (10·13) 는 무관하며 산출 불변이다.
    - 예: `` ````\n```js\ncode\n```\n```` `` → `pre` 1 · 코드 내용 세 줄(`` ```js `` · `code` · `` ``` ``). `~~~\ncode\n~~~` → `pre` 1 · 렌더 텍스트에 `~` 0. `` ```\na\n```` `` → `pre` 1 · 텍스트 `a` · 백틱 0.

## 동작 — 인라인

10. **다섯 구분자(`*` `**` `_` `__` `~~`) 는 공백 flanking 판정 아래 대등하다.** 여는 자리 뒤가 공백·줄끝이면 열지 않고, 닫는 자리 앞이 공백이면 닫지 않는다. `2 ** 10` · `와~~ 좋다 대박~~` · `값은 a _ b _ c 이다` 가 평문으로 남는다.

11. **문장부호 flanking**: 여는 구분자 뒤가 문장부호이고 앞이 공백도 문장부호도 아니면 열지 않는다. 닫는 쪽은 대칭이다. 판정면은 유니코드 `P`+`S` (`/[\p{P}\p{S}]/u`) 이며 ASCII 열거로 대신하지 않는다. **앞이 공백이거나 문장부호면 연다** — `**"굵게"**` · `(**굵게**)` · `~~"취소"~~`.

12. **낱말 안쪽 억제는 `_` 계열만이고, 앞뒤가 둘 다 단어 글자일 때만 발동한다.** `foo_bar_baz` · `a__b__c` 는 글자로 남고 `앞a~~b~~c뒤` 는 취소선이다.

13. **구분자 런은 쪼개 쓰지 않는다.** 여닫이 구분자 바로 바깥에 같은 글자가 이어지면 열지도 닫지도 않는다 (`___둘다___` · `아~~~ 그렇구나`).

14. **10~13 의 판정은 한 벌뿐이다.** 구분자별 사본을 만들지 않는다. 대등성은 **등록 인자가 아니라 산출로** 판정한다 — 같은 형태의 입력이 다섯 구분자 전부에서 같게 동작한다.

15. **보호 축**: 코드 스팬 안(`` `my_var_name` ``) · 백슬래시 이스케이프(`\_밑줄아님\_`) · 링크 URL 안(`/a_b_c`) 의 구분자는 강조가 아니다.

16. **링크 타깃**: 외부 URL 만 `target='_blank' rel='noreferrer'` 를 받는다. 내부·상대 링크는 같은 탭에서 연다.

## 동작 — 안전

17. **속성값은 보간 전에 escape 를 거친다.** `<img>`·`<a>` 의 속성값이 날것으로 들어가지 않는다. escape 함수의 정의는 `markdownParser.ts` 안에 있고 export 되지 않는다 — 사본이 갈라지지 않게.

18. **파서가 내는 태그와 속성은 정제를 통과한다.** `sanitizeHtml` 의 `ALLOWED_TAGS` 에 없는 태그를 파서가 emit 하면 글자가 통째로 사라지고, `ALLOWED_ATTR` 에 없는 속성은 조용히 지워진다. 두 목록은 함께 움직인다. 파서↔정제 정합 게이트의 corpus 는 **파서가 내는 속성마다 그 속성이 실제로 나오는 행**을 갖는다 — 1 로 시작하는 번호 목록은 `start` 를 내지 않으므로 그 행만으로는 정제 쪽 누락이 보이지 않는다.
