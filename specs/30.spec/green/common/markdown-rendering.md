## 역할

글쓴이가 쓴 것이 독자에게 그대로 보인다. **의도하지 않은 마크업이 글자를 삼키지 않고, 의도한 마크업이 글자로 남지 않는다.**

**방어 대상**: 파서가 조용히 내용을 바꾸는 회귀. 이 축의 실패는 게이트가 아니라 **독자가 먼저 본다** — 그리고 글쓴이는 자기 원문에서 잘못을 찾을 수 없다.

## 동작 — 블록

1. **ATX 제목의 닫는 `#` 은 내용이 아니다.** 줄 끝 `#` 런 앞에 공백이 있으면 닫는 시퀀스이며 개수는 여는 쪽과 무관하다. 앞에 공백이 없으면 내용이다 (`## C# 과 F#`). `####### 일곱` 과 `##제목` 은 여전히 문단이다.

2. **밑줄식 제목**: 문단 줄 바로 다음 줄이 `-` 만이면 `<h2>`, `=` 만이면 `<h1>` 이고 밑줄 줄은 남지 않는다. **바로 앞 한 줄만** 올라간다. 앞에 문단이 없으면 `<hr />` 이고, `*`·`_` 는 밑줄이 아니며, `- 항목\n---` 는 목록 + 가로줄이다.

3. **인용은 한 덩어리다.** 연속한 `>` 줄은 `<blockquote>` 하나이며 빈 줄에서 끊긴다. 인용 **안에서 블록 문법이 동작한다** — 목록·ATX 제목·밑줄식 제목·중첩 인용·**펜스 코드 블록** (`` > ``` `` 줄로 열고 닫은 블록 → `blockquote > pre`, 펜스 표기는 글자로 남지 않는다). 인용 내용의 인라인은 **한 번만** 처리된다.
    - **목록 항목의 내용으로 들어간 인용도 같다** (빈 줄 유무 무관). 줄 머리 인용과 같은 블록 판정 함수를 부르고 경로별 사본을 두지 않는다. `- a\n  > ```\n  > x\n  > ```` → `li > blockquote > pre` · 렌더 텍스트에 백틱 0 · 코드 줄은 인라인 처리를 받지 않는다. `- a\n  > # 제목` → `li > blockquote > h1` (`제목`). `- a\n  > - b\n  > - c` → `li > blockquote > ul > li` 2. 블록 문법 없는 항목 안 인용 `- a\n  > 인용문` 의 산출은 바뀌지 않는다.

4. **목록 항목의 내용은 마커 바로 뒤부터 시작한다.** 마커는 `-␣` 또는 `숫자.␣` 이며 그 전부가 표기다. 같은 내용을 두 표기로 쓰면 `<li>` 안 문자열이 같다.

5. **마커 없는 다음 줄은 그 항목의 내용이다** — 들여쓰기 유무와 무관하다. 목록은 끊기지 않고 **번호는 되감기지 않는다.** 들여쓰기로 쓴 공백·탭은 본문 앞에 남지 않는다. 열린 항목이 없는 들여쓴 줄은 그대로 문단이다 (`  hello` → `<p>  hello</p>`).

6. **빈 줄은 같은 종류의 목록을 끊지 않는다.** 산출이 그 줄을 걷어낸 입력과 문자열로 같다. 빈 줄 판정은 **공백·탭만 있는 줄을 포함**하며 그 술어는 파서 안에 하나뿐이다. 빈 줄 뒤가 목록이 아니거나 종류가 다르면 목록은 끝난다 — **단 내용 열까지 들여쓴 블록은 예외다 (19).**

7. **종류가 달라도 중첩된다.** 더 깊게 들여쓴 마커는 종류와 무관하게 그 항목 안에 중첩되고 바깥 목록의 여는 태그는 1개다. **같은 종류 중첩의 현 산출은 불변이다** — 종류 판정을 통째로 없애는 구현이 여기서 갈린다.

8. **파이프 표는 표로 렌더된다.**

9. **코드 블록 안의 마크다운은 파싱되지 않는다.** 들여쓰기·빈 줄·탭이 보존되고 HTML 은 이스케이프된다. 목록 항목 안에서 보존되는 것은 **내용 열 너머의** 들여쓰기다 — 내용 열까지는 항목의 표기다 (19).

### 블록 — 2026-10-13 흡수

19. **목록 항목의 내용 열까지 들여쓴 블록은 그 항목 안에 있다.** 내용 열은 마커 폭 + 뒤따르는 공백 수다 (`- `→2 · `1. `→3 · `10. `→4). 열린 항목의 내용 열 이상으로 들여쓴 펜스 코드 블록과 마커 없는 문단 줄은 **앞에 빈 줄이 있든 없든** 그 항목의 내용이고(`li` 의 자손), 그 뒤 같은 깊이·같은 종류 마커는 **같은 목록을 잇는다** — 여는 태그 1개, 번호는 되감기지 않는다. 항목 안 코드 블록의 각 줄에서 내용 열까지의 들여쓰기는 걷힌다. 빈 줄 뒤 블록이 내용 열 **미만**이면 목록은 끝난다 — `1. 첫째\n\n본문` 은 `<ol><li>첫째</li></ol><p></p><p>본문</p>` 그대로다. 내용 열 판정은 파서 안에 하나다.
    - 예: `1. 설치\n\n   ```\n   npm i\n   ```\n2. 실행` → `ol` 1 · `li` 2 · `pre` 는 첫 `li` 의 자손이고 `textContent` 가 `npm i` 로 시작한다. 빈 줄을 뺀 변형도 같다. `- 첫 문단\n\n  둘째 문단\n- 다음 항목` → `ul` 1 · `li` 2 · `둘째` 앞에 공백이 남지 않는다. `10. 열\n\n    본문\n11. 열하나` → `ol` 1 · `li` 2.
    - **마커 줄의 중첩 깊이(7)는 현 모델을 유지한다.** 내용 열은 마커 없는 블록의 귀속에만 쓴다. 두 판정을 하나로 합치면 `1. a\n  - b` (공백 2 < 내용 열 3) 처럼 지금 중첩되는 입력의 산출이 바뀐다.
    - **열린 항목은 현재 위치를 감싸는 마커 줄들의 열(바깥 → 안쪽)이다** — 가장 최근 마커 줄 하나가 아니다. 빈 줄 또는 코드 블록 뒤의 마커 없는 블록(문단 줄 · 펜스 코드 블록)은 들여쓰기가 내용 열 이상인 열린 항목 중 **가장 깊은 항목**의 내용이고, 그런 항목이 없으면 목록은 끝난다 (위 *"내용 열 미만이면 목록은 끝난다"* 의 일반화). 바깥 항목에 귀속된 블록은 그보다 깊은 항목들을 닫고, 그 뒤 같은 깊이·같은 종류 마커는 바깥 목록을 잇는다 — 여는 태그 1개, `start` 재발행 없음. 귀속된 블록 앞의 내용 열까지의 들여쓰기는 남지 않는다. `1. a\n   - b\n\n   본문\n2. c` → `ol` 1 · 바깥 `li` 2 · `본문` 은 첫 바깥 `li` 의 자손이고 `ul` 뒤에 오며 앞에 공백이 없다. 같은 자리의 펜스 코드 블록도 첫 바깥 `li` 의 자손이다. `- a\n  - b\n    - c\n\n    본문\n- d` → 최상위 `ul` 1 · `본문` 은 `b` 항목의 자손이고 `c` 항목의 자손이 아니다. 빈 줄 없는 이어짐은 5 를 따라 가장 안쪽 항목에 붙는다 — `1. a\n   - b\n   본문\n2. c` 의 `본문` 은 `b` 안이고 산출은 바뀌지 않는다.
    - **줄 머리 탭은 4칸 탭 정지까지의 공백으로 센다** (CommonMark §2.2). 마커 없는 블록이 내용 열에 닿았는지의 판정과 항목 안 코드 블록의 들여쓰기 걷기가 같은 셈을 쓰고, 그 셈은 파서 안에 하나다. `- 항목\n\t```js\n\tx\n\t```` → `li > pre` 1 · `pre` 텍스트 `x` · 렌더 텍스트에 백틱 0 · `js` 는 보이지 않는다. `- a\n\n\t본문\n- b` → `ul` 1 · `li` 2 · `본문` 은 첫 `li` 안이고 앞에 탭이 남지 않는다. 바뀌지 않는 것: 마커 줄의 중첩 깊이(둘째 하위 항목)와 최상위 탭 펜스 — 탭 하나는 4칸이므로 펜스가 아니다 (21, `\t```\n\tcode\n\t```` → `pre` 0).

20. **번호 목록은 글쓴이가 쓴 첫 번호부터 보인다.** 첫 항목 번호 N 이 1 이 아니면 정제를 거친 DOM 에서 그 `ol` 의 `start` 가 N 이다 (10진 정규화 — `003.` → `3`, `0.` → `0`). 첫 번호가 1 이면 `start` 를 내지 않는다 — `1. 하나\n2. 둘` 의 산출은 `<ol><li>하나</li><li>둘</li></ol>` 그대로다. 둘째 항목 이후의 번호는 매김에 영향이 없다 (`3. a\n7. b` → `start` 3, 항목 2). 중첩 번호 목록도 자기 첫 번호를 따른다. `start` 값은 숫자 문자만 담는다. 정제 쪽 조건은 `sanitizeHtml` (I15) 가 진다 — **한쪽만 고치면 독자에게는 아무 변화가 없다** (18).

21. **펜스 코드 블록은 여는 펜스의 문자·길이로 닫히고, 펜스 줄의 글자를 삼키지 않는다.** 펜스는 백틱 또는 물결 **3개 이상**이고 0~3칸 들여쓸 수 있다 (4칸 이상이면 펜스가 아니다). 닫는 펜스는 여는 펜스와 **같은 문자**이고 **개수가 같거나 많다** — 그보다 짧거나 다른 문자의 펜스 줄은 코드 내용으로 보인다. 여는 펜스가 N칸 들여쓰여 있으면 내용 각 줄에서 최대 N칸 걷힌다. 물결 펜스의 언어 표기와 하이라이트는 백틱 펜스와 같다 (`~~~kotlin` 의 산출 ≡ `` ```kotlin `` 의 산출). 펜스 판정은 파서 안에 하나이고 인용(3)·목록 항목(19) 안에서도 같은 판정을 부른다.
    - **펜스가 아닌 줄**: 백틱 펜스의 정보 문자열에 백틱이 있으면 그 줄은 문단이다 — `` ```인라인``` 문장\n다음 줄 `` → `pre` 0 · `code` 1(`인라인`) · `문장` 과 `다음 줄` 이 보인다. 물결 펜스는 정보 문자열이 비었거나 **언어 이름 꼴**(ASCII 영문으로 시작, 공백 없음)일 때만 펜스다 — `~~~ 그렇구나\n다음 줄` 은 문단이고 두 줄의 글자가 모두 보인다.
    - **CommonMark 와 갈리는 지점이다.** 표준은 물결 펜스의 정보 문자열을 제한하지 않는다. 그런데 정보 문자열은 화면에 나가지 않으므로, 표준대로면 한국어 늘임 표기(`~~~`)로 시작하는 산문 줄이 통째로 사라지고 닫는 펜스가 없으면 문서 끝까지가 코드가 된다. 줄 가운데의 `아~~~ 그렇구나` (10·13) 는 무관하며 산출 불변이다.
    - **목록 항목 안 펜스 코드 블록의 줄은 항목의 내용 열과 무관하게 다른 블록 판정을 받지 않는다** (9). 여는 펜스 줄부터 닫는 펜스 줄까지 밑줄식 제목·가로줄·표·인용·목록이 되지 않고, 하나의 `li > pre` 로 각 줄 텍스트가 보존되며, 그 뒤 같은 종류 마커는 같은 목록을 잇는다 (19). `10. 설정\n    ```yaml\n    a: 1\n    ---\n    b: 2\n    ```\n11. 다음` → `ol` 1 · `li pre` 1 · `h2` 0 · `pre` 텍스트 세 줄 `a: 1`·`---`·`b: 2`. 같은 자리에 `---` 한 줄만 두거나 `a | b\n--|--` 두 줄을 두어도 `hr` 0 · `table` 0 · `h2` 0 이다. 내용 열 3 이하 항목(`1. `)의 같은 입력은 지금도 그렇고 산출이 바뀌지 않는다.
    - 예: `` ````\n```js\ncode\n```\n```` `` → `pre` 1 · 코드 내용 세 줄(`` ```js `` · `code` · `` ``` ``). `~~~\ncode\n~~~` → `pre` 1 · 렌더 텍스트에 `~` 0. `` ```\na\n```` `` → `pre` 1 · 텍스트 `a` · 백틱 0.

22. **표 구분선의 정렬 표기는 그 열의 정렬로 보인다.** 구분선 셀 `:--` → 왼쪽, `:-:` → 가운데, `--:` → 오른쪽이고, 그 열의 `th` 와 모든 `td` 가 **열 위치로** 대응한다 (본문 행의 셀 수가 머리 행과 달라도). 표기 없는 열(`---`)의 셀에는 속성이 없고, 정렬 표기가 하나도 없는 표의 산출은 바뀌지 않는다 — `| 이름 | 값 |\n|---|---|\n| a | 1 |` 그대로. **정제 정책은 넓히지 않는다** (`sanitizeHtml` (I15) — `style`·`align` 부재). 정렬 표지는 정제 전후 같은 `class` 로 남는다.
    - **판정면은 계산된 스타일이다** — 전역 `th, td { text-align: left }` (`src/styles/typography.css`) 가 적용된 문서에서 `getComputedStyle(cell).textAlign`. class 문자열만 재면 CSS 쪽이 빠진 구현에서도 초록이다. `align` 속성은 그 작성자 CSS 에 져서 정제를 넓혀 통과시켜도 독자는 왼쪽 정렬을 본다.

## 동작 — 인라인

10. **다섯 구분자(`*` `**` `_` `__` `~~`) 는 공백 flanking 판정 아래 대등하다.** 여는 자리 뒤가 공백·줄끝이면 열지 않고, 닫는 자리 앞이 공백이면 닫지 않는다. `2 ** 10` · `와~~ 좋다 대박~~` · `값은 a _ b _ c 이다` 가 평문으로 남는다.

11. **문장부호 flanking**: 여는 구분자 뒤가 문장부호이고 앞이 공백도 문장부호도 아니면 열지 않는다. 닫는 쪽은 대칭이다. 판정면은 유니코드 `P`+`S` (`/[\p{P}\p{S}]/u`) 이며 ASCII 열거로 대신하지 않는다. **앞이 공백이거나 문장부호면 연다** — `**"굵게"**` · `(**굵게**)` · `~~"취소"~~`.

12. **낱말 안쪽 억제는 `_` 계열만이고, 앞뒤가 둘 다 단어 글자일 때만 발동한다.** `foo_bar_baz` · `a__b__c` 는 글자로 남고 `앞a~~b~~c뒤` 는 취소선이다.

13. **구분자 런은 쪼개 쓰지 않는다.** 여닫이 구분자 바로 바깥에 같은 글자가 이어지면 열지도 닫지도 않는다 (`___둘다___` · `아~~~ 그렇구나`).

14. **10~13 의 판정은 한 벌뿐이다.** 구분자별 사본을 만들지 않는다. 대등성은 **등록 인자가 아니라 산출로** 판정한다 — 같은 형태의 입력이 다섯 구분자 전부에서 같게 동작한다.

15. **보호 축**: 코드 스팬 안(`` `my_var_name` ``) · 백슬래시 이스케이프(`\_밑줄아님\_`) · 링크 URL 안(`/a_b_c`) 의 구분자는 강조가 아니다.

16. **링크 타깃**: 외부 URL 만 `target='_blank' rel='noreferrer'` 를 받는다. 내부·상대 링크는 같은 탭에서 연다.

### 인라인 — 2026-10-13 흡수

23. **코드 밖의 유효한 엔티티 참조는 그 문자로 보인다.** HTML5 이름 엔티티 · `&#`+10진 · `&#x`+16진이 대상이다 (`&copy;` → `©` · `&nbsp;` → U+00A0 · `&#35;` → `#` · `&amp;` → `&`). 무효한 코드 포인트와 `&#0;` 은 U+FFFD 다. 코드 스팬·코드 블록 안의 엔티티와 무효한 `&…;` (`AT&T` · `&없는이름;`) 는 지금처럼 글자다. `\&copy;` 는 글자 `&copy;` 다.
    - **해석된 문자는 마크업이 되지 않고 구조에 참여하지 않는다.** `&lt;script&gt;alert(1)&lt;/script&gt;` 는 글자 `<script>alert(1)</script>` 로 보이고 `script` 요소는 생기지 않는다. `&#42;굵게 아님&#42;` 은 `em` 을 만들지 않는다.
    - **파서 산출이 해석된 문자를 담는다** (필요한 escape 포함). 엔티티를 브라우저 해석에 맡기면 본문은 `©` 를, 요약은 `&copy;` 를 보인다 — `trimmedContents` 는 엔티티 다섯만 푼다. `trimmedContents("&copy; 2026")` 은 `"© 2026"` 이다.
    - 링크·이미지의 주소와 제목 안 엔티티도 해석된다 — `[x](https://example.com/?a=1&amp;b=2)` 의 실효 `href` 는 `https://example.com/?a=1&b=2` 다. 속성값 escape(17)는 해석 뒤에 건다. **참조 정의(24)의 주소·제목과 맨 URL(25)도 여기서 말하는 주소다** — `[x]\n\n[x]: https://a.example/?a=1&amp;b=2` 의 실효 `href` 는 `https://a.example/?a=1&b=2` 다.

24. **참조 링크는 정의된 주소로 연결된다.** `[텍스트][라벨]` · `[라벨][]` · `[라벨]` 은 문서 안에 `[라벨]: 주소` (선택적 제목 `"…"` · `'…'` · `(…)`) 정의가 있으면 그 주소·제목의 링크다. 정의는 사용 앞에 와도 뒤에 와도 된다. 라벨 대조는 대소문자 접기·앞뒤 공백 제거·내부 공백 연속 축약 뒤 같은지로 하고 (`[Foo  Bar]` ≡ `[foo bar]`), 같은 라벨의 정의가 여럿이면 첫 정의가 쓰인다. 정의가 없는 꼴은 지금처럼 글자다 (`대괄호 [메모] 와 느낌표 ![alt] 만 있다` 의 렌더 텍스트 === 입력). 링크 텍스트의 강조·`target`/`rel`·속성값 escape·정제는 인라인 링크와 같다 (15·16·17 — `[x]\n\n[x]: javascript:alert(1)` 에 `javascript:` 실효 `href` 0). 코드 스팬·블록 안의 정의 꼴과 참조 꼴은 링크가 아니며 그 안의 정의는 수집되지 않는다. 인라인 링크와 겹치면 인라인이 우선한다 (`[a](b)[c]` 에서 `[c]` 만 참조 후보).
    - **참조된 라벨의 정의 줄만 출력에서 걷히고, 참조되지 않은 정의 줄은 글자로 남는다 — CommonMark §4.7 과 의도적으로 갈린다.** 표준은 참조 여부와 무관하게 정의를 걷는다. 그러면 출처를 `[1]: https://…` 꼴로 나열만 해 둔 기존 글의 줄이 통째로 사라진다 (§역할). `[참고]: https://example.com` 한 줄뿐인 문서는 정의 줄이 `p` 하나로 남고 렌더 텍스트 === 입력이다. 그 줄 안의 주소가 링크가 되는지는 25 가 정한다 — 이 판정면은 25 착지 전후 모두 참이다.

25. **산문에 그냥 쓴 주소는 링크가 된다.** 코드 밖에서 줄 머리·공백 뒤·`*` `_` `~` `(` 뒤에 시작하는 `http://` · `https://` · `www.` 주소는 링크다. `www.` 는 `http://` 를 붙인 주소로 연결되고 (`www.example.com` → `http://www.example.com/`), 보이는 글자는 원문 그대로다 — 렌더 텍스트는 입력과 같다 (엔티티만 예외 — 아래 셋째 하위 항목).
    - **링크 밖에 남는 것**: 끝의 `?` `!` `.` `,` `:` `*` `_` `~` 와 짝 없는 닫는 괄호 (`(https://example.com).` → `(` + 링크 + `).`). 그리고 **호스트 바로 뒤에 공백 없이 붙은 한글** (`https://example.com에서 봐` → 링크 `https://example.com` + `에서 봐`). 경로 안의 한글은 링크에 포함된다 (`https://ko.wikipedia.org/wiki/서울`). 경로 끝에 붙은 조사(`…/서울에서`)는 구별할 수 없으므로 글쓴이는 꺾쇠 형태(`<…>`)를 쓴다 — 이 계약의 한계다.
    - **이중 링크·재가공 금지**: 코드 스팬·블록 안과 이미 링크인 텍스트(`[https://…](…)` 의 텍스트 · `<https://…>`) 안의 주소는 다시 링크가 되지 않는다 — `a` 안에 `a` 가 생기지 않는다. 맨 URL 안의 `*` `_` `~` 는 강조가 아니고 `href` 와 보이는 글자 모두 원문 그대로다 (15 — `https://example.com/a**b**c` → `strong` 0). 외부 주소의 `target`/`rel` 은 16 과 한 벌이다.
    - **맨 URL 안의 엔티티는 23 이 이긴다.** 링크의 범위는 원문 글자로 정한다 — 해석된 문자는 링크를 끊지도 늘리지도 않는다 (23 의 *"구조에 참여하지 않는다"*). `href` 와 보이는 글자는 23 의 해석을 거친다. `주소 https://example.com/?a=1&amp;b=2 를 본다` → `a` 1 · `href` 와 링크 `textContent` 모두 `https://example.com/?a=1&b=2` · 렌더 텍스트 `주소 https://example.com/?a=1&b=2 를 본다`. 같은 주소를 인라인 링크(23)로 쓴 것과 산출이 갈리지 않게 하려는 판정이다. markdown-it(`linkify`)은 원문 `&amp;` 를 그대로 두어 이 판정과 갈린다. GFM 은 주소 가운데의 유효 엔티티를 규정하지 않는다.

26. **코드 스팬은 백틱 N개 런으로 열고 바로 그 길이 N 의 백틱 런으로 닫는다** (CommonMark §6.1). 길이가 다른 백틱 런은 스팬 안의 글자이고, 여닫는 백틱은 렌더 텍스트에 남지 않는다 — ``` ``a ` b`` 끝 ``` → `code` 1 (텍스트 `` a ` b ``) · 렌더 텍스트 백틱 1. ```` ```인라인``` 문장 ```` → `code` 1 (`인라인`) · 백틱 0 (21 의 펜스가 아닌 줄). 스팬 내용이 공백으로 시작하고 공백으로 끝나며 공백만이 아니면 앞뒤 한 칸씩 걷는다 — ``` `` `x` `` ``` → `code` 1 · 텍스트 `` `x` ``. 같은 길이의 닫는 런이 없는 여는 런은 글자이고 스팬을 만들지 않는다 — ``` ``a` 끝 ``` → `code` 0 · 렌더 텍스트 === 입력. 겹 백틱 스팬 안의 구분자도 강조가 아니다 (15).
    - 바뀌지 않는 것: 홑 백틱 스팬 (`` `a` 끝 ``) · 스팬 안 백슬래시는 이스케이프가 아니다 (`` `a\` b `` → `code` 텍스트 `a\`) · 15 의 보호 축. 인용·목록 항목·표 칸 안에서도 같은 판정이고, 판정은 파서 안에 하나다.

## 동작 — 안전

17. **속성값은 보간 전에 escape 를 거친다.** `<img>`·`<a>` 의 속성값이 날것으로 들어가지 않는다. escape 함수의 정의는 `markdownParser.ts` 안에 있고 export 되지 않는다 — 사본이 갈라지지 않게.

18. **파서가 내는 태그와 속성은 정제를 통과한다.** `sanitizeHtml` 의 `ALLOWED_TAGS` 에 없는 태그를 파서가 emit 하면 글자가 통째로 사라지고, `ALLOWED_ATTR` 에 없는 속성은 조용히 지워진다. 두 목록은 함께 움직인다. 파서↔정제 정합 게이트의 corpus 는 **파서가 내는 속성마다 그 속성이 실제로 나오는 행**을 갖는다 — 1 로 시작하는 번호 목록은 `start` 를 내지 않으므로 그 행만으로는 정제 쪽 누락이 보이지 않는다.
