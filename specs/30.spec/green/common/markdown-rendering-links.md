> **위치**: `src/common/markdownParser.ts` (참조 정의 수집 · 링크·이미지 · 맨 URL · 꺾쇠 autolink · 속성값 복원) · `src/common/sanitizeHtml.ts` (정제) · 소비처는 `common/markdown-rendering` 과 같다

## 역할

`common/markdown-rendering` §역할 과 같다 — 글쓴이가 쓴 것이 독자에게 그대로 보인다. 이 문서는 그중 **링크·이미지가 어디로 가고 무엇을 보이는가**를 정한다: 링크가 되는 글자, 연결되는 주소, 속성값(`href` · `src` · `alt` · `title`)의 글자.

**방어 대상**: 파서가 링크의 글자·주소·속성값을 조용히 바꾸는 회귀. 독자는 다른 주소로 가거나, 화면 낭독기와 툴팁이 표기 문자를 읽는다. 렌더 텍스트만 재는 게이트에는 이 축이 보이지 않는다 (27 §참고 실측).

## 동작

24. **참조 링크는 정의된 주소로 연결된다.** `[텍스트][라벨]` · `[라벨][]` · `[라벨]` 은 문서 안에 `[라벨]: 주소` (선택적 제목 `"…"` · `'…'` · `(…)`) 정의가 있으면 그 주소·제목의 링크다. 정의는 사용 앞에 와도 뒤에 와도 된다. 라벨 대조는 대소문자 접기·앞뒤 공백 제거·내부 공백 연속 축약 뒤 같은지로 하고 (`[Foo  Bar]` ≡ `[foo bar]`), 같은 라벨의 정의가 여럿이면 첫 정의가 쓰인다. 정의가 없는 꼴은 지금처럼 글자다 (`대괄호 [메모] 와 느낌표 ![alt] 만 있다` 의 렌더 텍스트 === 입력). 링크 텍스트의 강조·`target`/`rel`·속성값 escape·정제는 인라인 링크와 같다 (15·16·17 — `[x]\n\n[x]: javascript:alert(1)` 에 `javascript:` 실효 `href` 0). 코드 스팬·블록 안의 정의 꼴과 참조 꼴은 링크가 아니며 그 안의 정의는 수집되지 않는다. 인라인 링크와 겹치면 인라인이 우선한다 — `[a](/b)\n\n[a]: /x` → `a` 1 · `href` `/b`. `[a](b)[c]` 에서는 `[c]` 만 참조 후보다 (이 예는 두 처리 순서에서 산출이 같아 우선순위를 증언하지 못한다).
    - **참조된 라벨의 정의 줄만 출력에서 걷히고, 참조되지 않은 정의 줄은 글자로 남는다 — CommonMark §4.7 과 의도적으로 갈린다.** 표준은 참조 여부와 무관하게 정의를 걷는다. 그러면 출처를 `[1]: https://…` 꼴로 나열만 해 둔 기존 글의 줄이 통째로 사라진다 (§역할). `[참고]: https://example.com` 한 줄뿐인 문서는 정의 줄이 `p` 하나로 남고 렌더 텍스트 === 입력이다. 그 줄 안의 주소가 링크가 되는지는 25 가 정한다 — 이 판정면은 25 착지 전후 모두 참이다.
    - **인라인 링크에 밀린 라벨은 참조되지 않은 것이다.** `[a](/b)\n\n[a]: /x` 의 정의 줄은 글자로 남고 렌더 텍스트는 `a[a]: /x` 다. 걷힘의 판정은 그 라벨이 참조 링크로 **해석됐는가**이고, 같은 라벨 꼴의 대괄호가 문서에 있는가가 아니다.
    - **정의는 최상위 문단 줄에서만 수집된다.** 인용·목록 항목 안의 정의 줄은 수집되지 않고 글자로 남으며, 그 라벨의 참조도 글자다 — 참조가 같은 컨테이너 안에 있어도 그렇다. `[a]\n\n> [a]: /q` · `[a]\n\n- [a]: /li2` · `- [a]\n\n  [a]: /li3` · `> [a]\n>\n> [a]: /q2` → `a` 0 · 렌더 텍스트 `[a][a]: /q` · `[a][a]: /li2` · `[a][a]: /li3` · `[a][a]: /q2`. CommonMark 은 넷 다 링크다 — 기능 부재이며 §미측정 에 있다. 게으른 이어짐으로 목록 항목에 흡수된 정의 꼴 줄(`- 항목 [a]\n[a]: /li`)은 정의가 아니라 문단의 이어짐이다 (CommonMark 과 같다 — 정의는 문단을 끊지 못한다): `a` 0 · 렌더 텍스트 `항목 [a][a]: /li`.
    - **라벨 대조는 백틱 런 길이를 구별한다.** 백틱은 라벨 문자열의 글자다 — 위 정규화(대소문자 · 앞뒤 공백 · 내부 공백) 밖의 접기를 라벨 키에 넣지 않는다 (CommonMark §4.7). ```[`a`]\n\n[``a``]: /x``` · ```[``a``]\n\n[`a`]: /x``` → `a` 0. 같은 표기는 계속 연결된다 — ```[``a``]\n\n[``a``]: /x``` · ``[`a`]\n\n[`a`]: /x`` → `a` 1 · `href` `/x`.

25. **산문에 그냥 쓴 주소는 링크가 된다.** 코드 밖에서 줄 머리·공백 뒤·`*` `_` `~` `(` 뒤에 시작하는 `http://` · `https://` · `www.` 주소는 링크다. `www.` 는 `http://` 를 붙인 주소로 연결되고 (`www.example.com` → `http://www.example.com/`), 보이는 글자는 원문 그대로다 — 렌더 텍스트는 입력과 같다 (엔티티만 예외 — 아래 셋째 하위 항목).
    - **링크 밖에 남는 것**: 끝의 `?` `!` `.` `,` `:` `*` `_` `~` 와 짝 없는 닫는 괄호 (`(https://example.com).` → `(` + 링크 + `).`). 그리고 **호스트 바로 뒤에 공백 없이 붙은 한글** (`https://example.com에서 봐` → 링크 `https://example.com` + `에서 봐`). 경로 안의 한글은 링크에 포함된다 (`https://ko.wikipedia.org/wiki/서울`). 경로 끝에 붙은 조사(`…/서울에서`)는 구별할 수 없으므로 글쓴이는 꺾쇠 형태(`<…>`)를 쓴다 — 이 계약의 한계다.
    - **이중 링크·재가공 금지**: 코드 스팬·블록 안과 이미 링크인 텍스트(`[https://…](…)` 의 텍스트 · `<https://…>`) 안의 주소는 다시 링크가 되지 않는다 — `a` 안에 `a` 가 생기지 않는다 (판정면은 28 둘째 하위 항목과 같다 — 원시 산출의 `a` 깊이와 정제 DOM 의 `a` 열이고 `a a` 0 은 판정이 아니다). 맨 URL 안의 `*` `_` `~` 는 강조가 아니고 `href` 와 보이는 글자 모두 원문 그대로다 (15 — `https://example.com/a**b**c` → `strong` 0). 외부 주소의 `target`/`rel` 은 16 과 한 벌이다.
    - **맨 URL 안의 엔티티는 23 이 이긴다.** 링크의 범위는 원문 글자로 정한다 — 해석된 문자는 링크를 끊지도 늘리지도 않는다 (23 의 *"구조에 참여하지 않는다"*). `href` 와 보이는 글자는 23 의 해석을 거친다. `주소 https://example.com/?a=1&amp;b=2 를 본다` → `a` 1 · `href` 와 링크 `textContent` 모두 `https://example.com/?a=1&b=2` · 렌더 텍스트 `주소 https://example.com/?a=1&b=2 를 본다`. 같은 주소를 인라인 링크(23)로 쓴 것과 산출이 갈리지 않게 하려는 판정이다. markdown-it(`linkify`)은 원문 `&amp;` 를 그대로 두어 이 판정과 갈린다. GFM 은 주소 가운데의 유효 엔티티를 규정하지 않는다.

27. **링크·이미지의 속성값과 꺾쇠 autolink 의 글자에는 파서 내부 자리표시자가 남지 않고, 인라인 표기는 자리마다 정해진 대로 풀린다.** 판정면은 정제를 거친 DOM 의 `getAttribute` 와 `textContent` 다.
    - **자리표시자 0**: 파서가 내는 어느 속성값(`a@href` · `a@title` · `img@src` · `img@alt` · `img@title`)에도, autolink 의 보이는 글자에도 파서 내부 자리표시자(U+E000–U+E006)가 없다. 자리표시자 집합과 속성 자리 목록은 파서 소스에서 도출하고 열거하지 않는다. 게이트 corpus 는 (자리표시자 종류 {백슬래시 이스케이프 · 엔티티 · 코드 스팬}) × (속성 자리) 의 **모든 칸**에 행을 갖는다 — 속성 안에 이스케이프·코드 스팬이 든 행이 없으면 조각 안 복원을 지운 트리가 초록이다 (§참고 실측).
    - **구조 표식도 속성값에 태그 글자로 들지 않는다.** 항목 이어짐(줄 이음)과 변경 이력 강조 구간(`HIGHLIGHT_OPEN` · `HIGHLIGHT_CLOSE` — `components/writer-change-history-highlight`)의 표식이 링크·이미지 표기 안에 떨어져도 `img@alt` · `img@title` · `a@title` 에 그 표식에서 나온 `<br />` · `<span class="span--logitem-changed">` · `</span>` 글자가 없다. **줄 이음은 속성값에서 줄바꿈(U+000A) 한 글자다** — 두 줄에 걸친 설명·제목의 낱말이 붙지 않고 이어짐 줄 앞 들여쓰기는 남지 않는다 (CommonMark 과 같다): `- ![a\n  b](…)` · `1. ![a\n   b](…)` → `alt` === `"a\nb"` (JS 리터럴) · `- ![a\n  b\n  c](…)` → `"a\nb\nc"` · `- [x](https://example.com/u "a\n  b")` → `a@title` === `"a\nb"` · `- ![x](https://example.com/x.png "a\n  b")` → `img@title` === `"a\nb"`. 강조 표식은 속성값에서 걷힌다 — 설명 `a` + U+E002 + `b` + U+E003 + `c` → `alt` `abc`. 사용자가 쓴 꺾쇠 글자는 대상이 아니다 (`![a <b> c](…)` → `alt` `a <b> c`). 위 자리표시자 0 의 판정(U+E000–U+E006 계수)은 이 누출을 보지 못한다 — 표식이 이미 태그 글자로 바뀐 뒤다.
    - **주소·제목**: 백슬래시 이스케이프는 풀리고 (`[x](https://example.com/a\_b)` → `href` `https://example.com/a_b` · 이미지 `src` 도 같다), 엔티티는 해석되며 (23), 백틱은 글자다 (`` [x](https://example.com/?q=`v`) `` → `href` `` https://example.com/?q=`v` `` · 제목 `` "제목 `c` \_ &copy;" `` → `title` `` 제목 `c` _ © ``). CommonMark 과 같다.
    - **주소·제목 · 꺾쇠 autolink 안의 백틱은 쓴 그대로다.** 이 자리에서 백틱은 코드 스팬이 아니라 글자이므로 26 의 런 판정과 앞뒤 한 칸 걷기를 받지 않는다 — 런 길이와 런 사이의 공백을 포함한 원문이 속성값과 autolink 글자에 들어간다. ```[x](https://example.com/?q=``v``)``` → `href` ``` https://example.com/?q=``v`` ``` · `` [x](/u "제목 ` c ` 끝") `` → `title` `` 제목 ` c ` 끝 `` · 참조 정의 ```[``a``]: /x "t ``b``"``` 의 제목 → ``` t ``b`` ``` · ```<https://example.com/?q=``v``>``` → `href` 와 글자 모두 원문. 백틱 사이의 백슬래시 이스케이프도 이 자리에서는 풀린다 — `` [x](/u "`a\_b`") `` → `title` `` `a_b` `` · `` [x](https://example.com/`a\_b`) `` → `href` 에 `\` 0 (위 *"백슬래시 이스케이프는 풀리고"* 의 귀결). `alt` 는 아래 평문이라 런 길이와 무관하게 코드 스팬 내용만 남는다 — ```![``a`` 그림](/i.png)``` · `` ![` a ` 그림](/i.png) `` → `a 그림`.
    - **인라인 링크·이미지의 제목은 `"…"` · `'…'` · `(…)` 세 표기를 받는다** — 참조 정의(24)와 한 벌이며 표기 규칙의 사본을 두지 않는다. 같은 제목 문자열을 세 경로(인라인 링크 · 인라인 이미지 · 참조 정의)에 쓰면 `title` 이 같다. `[x](https://example.com '제목')` · `[x](https://example.com (제목))` → `a` 1 · `href` `https://example.com` · `title` `제목` · 텍스트 `x` · `![x](https://example.com/i.png '그림 제목')` → `img` 1 · `title` `그림 제목` · `[x](/u '제목 "따옴"')` → `title` `제목 "따옴"`. 새 표기의 제목에도 위 이스케이프·엔티티 해석과 17 의 속성값 escape 가 걸린다. 바뀌지 않는 것: 큰따옴표 제목 · 참조 정의의 작은따옴표 제목 · 짝이 안 맞는 작은따옴표(`[x](https://example.com 'it''s')` 는 링크가 아니고 안의 주소만 25 의 맨 URL 이다).
    - **이미지 `alt` 는 설명의 평문이다** — 설명을 본문으로 렌더한 결과의 글자이고, 설명 안 이미지는 자기 `alt` 를 글자로 낸다. 단 줄 이음은 본문의 `<br>` 을 따르지 않고 줄바꿈 한 글자다 (위 구조 표식 하위 항목). 설명 안 꺾쇠 autolink 는 주소 글자만 남는다 — 본문 렌더 글자와 같다: `![<https://example.com/a>](…)` → `https://example.com/a` · `![<https://example.com/a?x=1&amp;y=2>](…)` → `https://example.com/a?x=1&y=2` (아래 autolink 하위 항목과 한 벌). 코드 스팬은 내용만 남고, 강조·취소선 구분자는 남지 않으며, 이스케이프·엔티티는 풀린다: `` ![`c`](…) `` → `c` · `![**굵게** 그림](…)` → `굵게 그림` · `![*기울임*](…)` → `기울임` · `![a ~~b~~ c](…)` → `a b c` · `![a\_b](…)` → `a_b` · `![a &copy; b](…)` → `a © b`. 화면 낭독기와 이미지가 안 뜰 때의 글자가 표기 문자를 읽지 않게 하려는 것이다 (§역할). CommonMark §6.4 의 *"plain string content"* 와 같다 — 취소선은 GFM 확장이지만 이 파서가 본문에서 `del` 로 내므로(10) `alt` 에서도 걷는다.
    - **꺾쇠 autolink 의 `href` 와 보이는 글자는 같고, 같은 주소를 인라인 링크 `[u](주소)` 로 쓴 것의 실효 `href` 와 같다.** 엔티티는 해석되고 (`<https://example.com/?a=1&amp;b=2>` → 둘 다 `https://example.com/?a=1&b=2`) 백슬래시 이스케이프는 풀린다 (`<https://example.com/a\_b>` → 둘 다 `https://example.com/a_b`). 세 링크 형태의 실효 주소가 같아야 한다는 25 셋째 하위 항목의 원리와 한 벌이다.
    - **백슬래시 쪽은 CommonMark 예제 603 과 의도적으로 갈린다.** 표준은 autolink 안 이스케이프를 풀지 않는다. 그러나 남긴 `\` 를 브라우저 URL 파서가 특수 스킴에서 `/` 로 읽고 (`new URL("https://example.com/a\\_b").href` → `https://example.com/a/_b`, WHATWG URL §path state), 이 파서에는 주소를 인코딩하는 단계가 없다. 엔티티 쪽은 cmark 와 §2.5 문면(*"including URLs"*)을 따르며 commonmark.js 와 갈린다.
    - 바뀌지 않는 것: 속성값 escape 는 해석 뒤에 건다 (17). 강조는 속성값에 파고들지 않는다 (`markdown-attribute-integrity.test.ts`). 링크 텍스트의 강조는 유지된다. 구두점이 아닌 문자 앞의 백슬래시는 글자다 (`![C:\Users](x.png)` → `alt` `C:\Users`).

28. **링크 텍스트와 이미지 설명 안의 짝 맞는 대괄호는 링크·이미지를 깨지 않는다** (CommonMark §6.3 — *"backslash-escaped or … a matched pair of brackets"*). 짝이 맞는 대괄호는 중첩돼도 텍스트 안에 들고, 어느 경우에도 렌더 텍스트에 `](` 가 남지 않는다. `[arr[0] 접근](https://example.com/)` → `a` 1 · 텍스트 `arr[0] 접근` · `[a [b] c](https://example.com/)` → `a [b] c` · `[link [foo [bar]]](/uri)` → `link [foo [bar]]` · `![그림 [1]](https://example.com/x.png)` → `img` 1 · `alt` `그림 [1]`.
    - **이미지 설명 안의 링크·이미지는 바깥 이미지의 설명이다.** `![foo [bar](/url)](/url2)` · `![foo ![bar](/url)](/url2)` → `img` 1 · `src` `/url2` · `alt` `foo bar` (27 의 평문) · 렌더 텍스트와 요약(`trimmedContents`)에 `](` 0.
    - **대괄호 링크 안에 링크는 생기지 않는다** — 인라인 링크 · 참조 링크(24)의 텍스트 안에 대괄호 링크나 맨 URL(25)이 있으면 둘이 겹치지 않는다. 짝 판정만으로 구현하면 바깥 대괄호가 짝이 맞아 `a` 안에 `a` 가 생긴다. **판정면은 겹침이 드러나는 곳이다** — `markdownToHtml` 원시 문자열의 `<a` 여닫이 깊이가 1 을 넘지 않고, 정제를 거친 DOM 의 `a` 열(`[textContent, href]`)이 CommonMark 과 같다. 정제 DOM 의 `a a` 는 판정이 아니다 — HTML 파서는 열린 `a` 안의 `a` 시작 태그에서 바깥 `a` 를 닫으므로 원시 산출이 겹쳐도 언제나 0 이다 (WHATWG HTML §13.2.6.4.7 · REQ-20261013-132 실측 — 겹친 5행 전부 `a a` 0). 인라인 바깥 꼴과 **참조 링크 바깥 꼴**이 같은 판정을 받는다: `[foo [bar](/uri)](/uri)` (예제 518) → `a` 열 `bar`→`/uri` · `[foo [bar](/uri)][ref]\n\n[ref]: /uri` (예제 532) → `bar`→`/uri` · `ref`→`/uri` · 렌더 텍스트 `[foo bar]ref` · `[foo *bar [baz][ref]*][ref]\n\n[ref]: /uri` (예제 533) → `baz`→`/uri` · `ref`→`/uri` · `[a [b](/u) c][ref]\n\n[ref]: /r` → `b`→`/u` · `ref`→`/r` (목록 항목 안도 같다). 금지가 지금 판정 한 곳을 공유한다는 사실이 참조 바깥 꼴의 공백을 가린다 — 두 경로가 갈라지면 게이트 없이 깨진다 (req 주입 I1).
    - **꺾쇠 · `mailto:` autolink 는 이 금지 밖이다** (REQ-20261013-132 FR-04 (i) 채택). 링크 텍스트 안의 꺾쇠 autolink 는 원시 산출에서 `a` 를 겹치고 독자에게는 바깥 링크가 쪼개져 보인다 — `[see <https://example.com> here](/u)` → `a` 열 `see `→`/u` · `https://example.com`→같은 주소, ` here` 는 링크 밖 글자. commonmark.js 0.31.2 의 HTML 도 같은 자리에서 겹친다 (§미측정). 정제 DOM 의 `a` 열은 commonmark.js 와 같다.
    - **짝 없는 `[` 는 글자이고 링크는 짝이 맞는 `[` 부터다** — `[link [bar](/uri)` → 글자 `[link ` + `a` (`bar`) (예제 514).
    - **대괄호 짝 판정은 파서 안에 하나다.** 인라인 링크·이미지·참조 링크(24)가 같은 판정을 부른다 — `[link [foo [bar]]][ref]\n\n[ref]: /uri` → `a` 1 · 텍스트 `link [foo [bar]]` (예제 528).
    - **맨 URL(25)과의 관계**: 대괄호 때문에 인라인 링크가 서지 못하면 `(…)` 안의 주소가 맨 URL 링크가 된다. 28 착지 후 그 주소는 `href` 안에 있고 다시 링크가 되지 않는다 (25 *"이중 링크·재가공 금지"*). 판정은 링크 수가 아니라 링크의 텍스트와 렌더 텍스트의 `](` 로 한다 — HEAD=`cb354da` 에서 `[arr[0] 접근](https://example.com/)` 은 이미 `a` 1 (텍스트 `https://example.com/`) 이다.
    - 바뀌지 않는 것: 짝 없는 `]` 는 글자다 (`[link] bar](/uri)` → `a` 0 · 렌더 텍스트 === 입력). 이스케이프된 대괄호는 글자다 (`[a \] b](https://example.com/)` → `a` 1 · 텍스트 `a ] b`). 링크 안 이미지(`[![배지](https://example.com/b.svg)](https://example.com/)` → `a > img` · `alt` `배지`). 주소의 균형 괄호 한 겹. 링크 URL 안의 구분자는 강조가 아니다 (15). 링크 텍스트의 강조는 유지된다.

- 링크 텍스트 안의 꺾쇠 · `mailto:` autolink 는 28 둘째 하위 항목의 금지 밖이다 (REQ-20261013-132 FR-04 (i)). 원시 산출은 `a` 를 겹치고 (`<a href='/u'>see <a href='https://example.com' …>https://example.com</a> here</a>`), 독자에게는 바깥 링크가 쪼개진다 — `see `→`/u` · 주소→주소 · ` here` 는 링크 밖 글자. commonmark.js 0.31.2 의 HTML 도 같은 자리에서 겹친다 (REQ-132 생성 120행 중 30행 — 안쪽이 꺾쇠 · `mailto:` autolink 인 행 전부). 원인은 autolink 패스가 링크 패스보다 먼저 돌고 링크 패스가 텍스트 안 autolink 자리표시자를 링크로 세지 않는 처리 순서다. 금지 대상으로 넓히면 (ii) 참조 구현과 갈리고 바깥 · 안쪽 중 무엇을 링크로 남길지 정해야 한다 — 넓힐 때는 이 줄과 28 둘째 하위 항목을 함께 뒤집는다.
- 예제 518 (`[foo [bar](/uri)](/uri)`) 의 산출은 HEAD=`d4b8ef0` 에서 commonmark.js 와 같다 — 안쪽 링크가 살고 바깥 대괄호가 글자다 (`[foo <a>bar</a>](/uri)`, 렌더 텍스트 `[foo bar](/uri)`). 28 은 그 `a` 열을 계약한다. 남는 글자가 어느 대괄호인지는 `a` 열과 렌더 텍스트로 정해지며 따로 계약하지 않는다.
- 27 의 귀결로 `<https://example.com/\[\>` (CommonMark 예제 603 원문) 은 링크가 되지 않는다 — `\>` 가 이스케이프로 먼저 소비돼 닫는 꺾쇠가 없고, 보이는 글자는 `<https://example.com/[>` 다. 주소의 퍼센트 인코딩은 이 파서에 없고 27 은 그것을 들이지 않는다.
- 참조 이미지(`![alt][라벨]`)·여러 줄에 걸친 참조 정의·**인용·목록 항목 안의 참조 정의**는 미구현이다. 고장이 아니라 기능 부재이며 사용 빈도를 주장할 근거가 없다. 컨테이너 안 정의의 글자는 다 보인다 (24 셋째 하위 항목).
- 컨테이너 안 정의 중 참조와 **같은** 컨테이너에 든 것(`- [a]\n\n  [a]: /li3` · `> [a]\n>\n> [a]: /q2`)만 수집하는 확장은 채택하지 않았다 (REQ-20261013-110 FR-04 Could). 그러면 같은 정의가 바깥 참조에는 글자, 안쪽 참조에는 링크인 산출이 된다 — CommonMark(문서 전역 수집)과도 현 동작과도 다른 제3의 산출이다. 넓힐 때는 넷을 함께 넓히고 24 셋째 하위 항목을 뒤집는다.
