# markdown-pipe-table 격리 사유 — (I9) 의 선언 창과 계수 창이 갈렸다

> 격리자: planner 388차 tick · 측정 HEAD=`41d5dd3` · 경로 `30.spec/blue` → `50.blocked/spec`
> 근거 규약: `RULE-07 §처리` (수동 발견) · `RULE-01` (blue 는 planner `mv` 만) · `RULE-05` (해제는 운영자)

## 무엇이 틀렸나

§동작 (I9) 는 이렇게 선언한다:

> **표 태그가 `ALLOWED_TAGS` 에 오르면 corpus 에 표 입력이 1행 이상 있어야 한다.**

그런데 §테스트 현황 (I9) 판정 명령의 계수 채널 `c` 는 **게이트 파일 전역**(주석 제외)이다. `corpus` 블록을 창으로 삼는 것은 모집단 하한 `r` 뿐이다.

```
r=$(awk "/^const corpus/{k=1;next} /^\];/{k=0} k" "$f" | grep -c "^[[:space:]]*\[")   # corpus 블록 창
c=$(grep -vE "^[[:space:]]*(//|\*)" "$f" | grep -cE "<table|[|]---")                  # 파일 전역 창
```

**선언은 `corpus` 를 말하고 판정은 파일 전체를 센다.**

## 실측 (planner 388차, `git clone --local` 격리 사본, 메인 트리 쓰기 0)

| 상태 | 출력 | rc |
|---|---|---|
| clean | `allowed-table-tags=6 corpus-rows=14 table-bearing-inputs=7` | 0 |
| **corpus 의 `파이프 표` 행 제거** (= 선언 명제 직접 위반) | `allowed-table-tags=6 corpus-rows=13 table-bearing-inputs=6` | **0** |
| 원복 | `… inputs=7` | 0 |

**선언한 명제를 직접 위반해도 게이트가 초록이다.** `corpus` 블록 안의 hit 은 1건뿐이고 나머지 6 은 창 밖에 있다:

- `:82` — `sanitizer 는 표 트리를 보존한다` 테스트의 fixture
- `:117`~`:121` — `PARENT_CONTEXT` 맵 (`thead`/`tbody`/`tr`/`th`/`td` 의 부모 문맥 표기)

`:117`~`:121` 은 **이 계약과 무관한 이유로 생긴 구조 데이터**다 — `72e062a`(*refactor: 정책 커버리지 판정 모집단을 소스 표기에서 효력면으로 옮긴다*)가 효력면 도출을 세우며 넣었다. 그 5줄만으로 `c >= 1` 이 영구히 참이 되므로, **corpus 와 `:82` 를 둘 다 지워도 게이트는 초록이다.**

## 인계받은 수치와 다른 점

inspector 257차는 `전역 2 hit / corpus 안 1 hit` 로 보고했다. **388차 재실측은 `전역 7 hit / corpus 안 1 hit` 이다.** 늘어난 5는 위 `PARENT_CONTEXT` 항목이며 그 사이 `72e062a` 가 착지했다. **드리프트는 보고 이후 더 벌어졌다** — 넘겨받은 수치를 옮겨 적지 않고 다시 잰 이유가 이것이다.

## 채널을 넓힌 253차 판단은 옳았다 — 되돌리지 말 것

계수 채널을 `corpus` 안의 `|---` 에서 파일 전역으로 넓힌 것은 **`RULE-06 §음성 대조` 를 따른 정당한 판단**이었다. 당시 파서가 표를 내지 못해 마크다운 원문 `|---` 요구는 충족 **불가능**했고, developer 가 세운 HTML 직접 입력이 계약의 뜻을 만족했다. 정상 변형 쪽을 고치지 않은 것이 맞다.

**남은 결함은 넓힌 것 자체가 아니라 §동작 문면이 여전히 `corpus 에` 를 말한다는 점이다.** (I7) 이 요구하는 *"대리 표면을 아는 채로 유지한다면 그 사실과 좁힘 경로를 문면에 박제한다"* 가 §테스트 현황 에만 있고 §동작 에는 반영되지 않았다.

## 왜 blue 격리인가 — 다른 경로가 없다

- `30.spec/blue/**` 는 **어느 에이전트의 편집 영역도 아니다** (`RULE-01` 쓰기 권한 매트릭스). inspector 는 green 만, planner 는 `mv` 만 한다.
- 이 항목은 §수용 기준 `(Must, REQ-067 FR-01·FR-02 모집단 결합)` 의 **유일한 판정 채널**이다. 민감도 0 인 판정 항은 `RULE-07 §promote 조건 2`(측정 명령 전수 rc=0)를 **언제나** 만족시키므로, 이 상태로 두면 재승격 시에도 통과한다.
- 따라서 `RULE-07 §처리` 의 **수동 발견** 경로(`30.spec/**` → `50.blocked/spec/`)가 유일한 정정 입구이고 그 `mv` 권한은 planner 다.

## 해제 시 무엇을 고치면 되나 (제안 — 판단은 운영자·discovery)

둘 중 하나이며 **둘 다 정당하다**. 어느 쪽이든 §동작 과 §테스트 현황 이 **같은 창을 말하게** 하는 것이 요점이다.

1. **문면을 창에 맞춘다** — §동작 (I9) 를 *"corpus 에"* 가 아니라 *"정합 게이트에 표를 담은 입력이 있다"* 로 고치고, 계수 창이 파일 전역이라는 사실과 그 사유(파서 미착지 시 HTML 직접 입력 허용)를 §동작 에 박제한다. **가장 값싼 정정이며 253차 판단을 그대로 보존한다.**
2. **창을 문면에 맞춘다** — 계수 창을 *"corpus 블록 + `directFixtures` 대역"* 으로 한정해 `PARENT_CONTEXT` 같은 구조 데이터를 모집단에서 뺀다. 이쪽을 고르면 **좁힘이 완화로 미끄러지지 않았음을 왕복으로 확인해야 한다** (출처 spec (I7) — 좁힘과 완화는 같은 편집 방향이다).

어느 쪽이든 정정 후 **주입 왕복**으로 닫는다: corpus 의 표 행 제거 → `rc≠0` · 정책에서 표 태그 제거 → `rc=0`(공허 참 복귀) · `PARENT_CONTEXT` 에 항목 추가(정상 변형) → `rc=0` 유지.

## 격리하지 않은 것

- **계약 자체는 건전하다.** 표 렌더 축(§동작 (I1)~(I8))과 `<table>` 정합 축은 이 결함과 무관하며, 이 격리는 그 축을 폐기하자는 뜻이 아니다.
- `src/**` 는 **건드리지 않았다.** 위 실측은 전부 저장소 밖 `git clone --local` 사본에서 했고 원복까지 확인했다.

## 의문 (이동한 뒤 적는다 — `RULE-03 §(S3)` 형식)

격리가 이 결함에 **비싼 도구**일 수 있다. 고칠 것은 §동작 한 문단이고, blue 편집 writer 가 없다는 구조 때문에 전체 문서가 파이프라인 밖으로 나간다. `RULE-01` 매트릭스에 *"blue 문면 정정"* 창구가 없다는 것이 이 비용의 원인이며, 그것을 규약으로 다룰지는 운영자 판단이다 (`rules/` 는 운영자 전용). **그럼에도 이동한 이유는 대안이 "알면서 방치" 뿐이기 때문이다.**
