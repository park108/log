# RULE-06 Task 스코프 & grep 게이트

작업지시서 `## 검증/DoD` 에 `grep -rn <pattern> <path> → 0 lines` 형태 게이트가 1건 이상이면 **`## 스코프 규칙` 섹션 필수**. 없으면 생략 가능.

## 섹션 스펙
```markdown
## 스코프 규칙
- **expansion**: 허용 | 불허 | N/A
- **grep-baseline**:
  - `grep -rn "<pattern>" <path>` → N hits in M files:
    - `src/foo.js:12`
    - `src/bar.test.js:34, 56`
- **rationale**: <1~2줄>
```

## expansion 의미
- **허용**: baseline 열거 scope 밖 파일도 게이트 충족 목적으로 정상화 가능.
- **불허**: scope 밖 변경 금지. 게이트 위반 파일이 scope 밖이면 developer 는 즉시 `50.blocked/task/` 격리.
- **N/A**: grep 게이트 없음.

## 역할
- **planner / inspector**: 작성 시점에 `grep-baseline` 실제 실행 결과 박제.
- **developer**: 수행 전 섹션 읽고 `expansion` 에 따라 행동. 섹션 부재면 `## 변경 범위` 만 준수.

## 정밀 패턴 권고

> **도구 가용성 (2026-08-26 실측)** — `rg` 는 **바이너리가 없고 CI 에도 설치 단계가 없다**. baseline 은 실제 실행 결과 박제가 의무이므로 `rg` 로 쓴 게이트는 작성 시점에 실패한다. `grep -rnE` 를 쓴다 — `/usr/bin/grep` 은 BSD grep 2.6.0 (GNU 호환) 으로 `\s`·`\b` 를 **둘 다 지원**한다 (실측: `grep -cE "\bbar\b"` 가 `foobar` 를 정확히 배제). 반면 **`sed -E` 는 `\b` 를 지원하지 않는다** — `s/\bbar\b/X/` 가 조용히 무치환으로 끝나므로 rename 류를 sed 로 하면 선언 라인만 바뀌고 나머지가 남는다 (실제로 발생). 대화형 zsh 에서 `grep` 은 셸 함수로 가로채이므로 **`bash -c "..."` 로 감싸 실행**한다. 멀티라인은 `perl -0777 -ne`. BRE(`grep` 기본)에서 `\(` 는 **캡처 그룹**이라 괄호 리터럴을 찾으려면 `-E` + `\(` 이거나 `-F` 다 — 이 혼동으로 64건 있는 트리에서 0 hit 을 낸 baseline 이 실제로 발행됐다.

> **쓰기 실패 검출 (2026-09-01 실측)** — 읽기 쪽의 쌍둥이다. **`>` 는 앞 명령이 실패해도 파일을 먼저 비운다.** 리다이렉션의 truncate 는 명령 실행 **전에** 일어나므로, 명령이 죽어도 파일은 이미 0바이트다. 같은 형태가 프로그램 안에도 있다 — `open(p,'w')` 는 그 시점에 자르고 뒤이은 `write()` 가 예외로 죽으면 **내용만 사라진다.** 실측 2건: `head -n -1 f > f` 형태가 BSD `head` 의 음수 거부와 겹쳐 ndjson 이력을 잘랐고, `re.subn` 반환 튜플을 뒤집어 쓴 스크립트가 green spec 을 0바이트로 만들었다.
>
> **원본을 덮어쓰는 자리에서는 임시 파일에 쓰고 성공을 확인한 뒤 `mv` 한다.** 이력 파일은 **append 만** 한다 — 이미 쓴 줄은 틀렸어도 고치지 말고 다음 줄에 정정값을 쓴다. 이력에서 과거를 고치는 것은 이력이 아니게 만드는 일이다. 두 사고 모두 **고치려는 행위 자체가 손실을 만들었다.**

> **추출 실패 검출 (2026-08-26 실측)** — spec 본문의 명령은 **손으로 옮겨 적지 말고 파일에서 추출해 실행**한다. 손 전사는 명령을 조용히 **바꾼다** (문자 클래스 안의 backtick 이 잘려 있었는데 전사하며 무의식적으로 복원해, 도달 불가 명령이 4 tick 동안 `rc=1` 로 오보됐다). 그러나 추출에도 대칭적 함정이 있다: **인라인 span 이 닫는 backtick 없이 끝나면 추출 결과가 빈 문자열이고, `bash -c ""` 는 `rc=0` 이다.** 미실행이 통과로 읽힌다 — 2026-08-26 에 green spec 1건에서 3건 발견됐고 그중 1건이 실제로 빈 추출에 `rc=0` 을 냈다. **따라서 추출 직후 비어 있지 않음을 단언하고, 추출한 문자열을 출력에 박제한 뒤 실행한다.** 무엇을 실행했는지 보이지 않는 rc 는 증거가 아니다.

- **afterEach 등록 잔존 검증**: `afterEach\s*\([^)]*<fn>\s*\(\s*\)` 형태 **등록 한정 패턴** 사용. `it` 본문 직렬 호출 오인 방지. 예: `grep -rnE "afterEach\s*\([^)]*vi\.useRealTimers\s*\(\s*\)" src --include="*.test.js" --include="*.test.jsx"`. 멀티라인은 `perl -0777 -ne '...'` 또는 `-A 3` 컨텍스트 + 수동 필터.
- **블록 경계 false-positive**: `[\s\S]*?` 는 경계 미존중 — 인접 `afterAll {...}` 까지 매치. 블록 내부 한정은 `[^{}]*?`, nested 허용 시 `(?:[^{}]|\{[^{}]*\})*?`. 검증: block 1 에서 1 hit, 인접 block 2 동일 token 미매치.
- **관측 표면**: 게이트는 production 이 소비하는 표면(빌드 산출물 · 등록된 chain · 실제 로드 경로)을 측정한다. 단위 격리 import 만으로 등록·연결을 단정하지 않는다 — 함수는 살아 있는데 plugins chain 에서 빠진 회귀가 그렇게 통과했다.
- **열거 고정 금지**: 측정 대상 목록은 glob/디렉터리 열거로 산출한다. 하드코딩이 불가피하면 목록 완전성 보조 단언을 함께 박제한다 — 하드코딩된 5개 스크립트 목록이 이후 추가된 6개를 스캔 범위 밖에 숨겼다.
- **fixture 대표성**: fixture 는 실코드의 표기 변형(들여쓰기 · 컬럼 위치)을 최소 1개 포함한다 — 들여쓰기 fixture 만 있어 greedy `\s*` 가 후속 매치를 삼키는 것이 관측되지 않았다.
- **grep-count**: `grep -c` 는 구조 인식 불가. `grep -cE "^[[:space:]]*<token>\s*\("` 로 본문 호출 한정 + baseline 에 제외 규칙·수치·샘플 라인 박제.

## 체크리스트 (planner / inspector)
baseline 실제 실행·수치 복사 / multiline 은 block boundary fixture 통과 / count 는 import·주석 제외 계산법 명시.

**fixture probe 경로 사전 점검** — 신규 fixture·probe 파일 경로를 baseline 에 박제하기 전 `grep -nE "^<path-prefix>" .gitignore` → **0 hit** 확인. hit 이 있으면 그 경로의 산출물은 커밋되지 않고 조용히 휘발하며, grep 게이트는 파일 부재를 위반이 아니라 통과로 읽는다 (false-negative).

## 게이트 실효 검증 (injection)

게이트(grep 게이트 · `check:*` script · fixture)를 **신설·수정하는 task** 는 아래를 DoD 항목으로 명기한다.

> spec 이 선언한 **검출 방향별로** 위반 1건 주입 → `rc≠0` 확인 → 원복 → `rc=0` 확인. 방향별 주입 명령과 출력을 `result.md` 에 박제한다.

- **방향 수는 spec 의 검출 선언에서 계수한다.** "양방향 검출" 을 선언했으면 2방향 전부 주입한다.
- `RULE-04` notes 에 `injection: N/N detect` 박제.
- 게이트 신설·수정 task 한정 — 일반 task 에는 적용하지 않는다.

### 음성 대조 (control) — 2026-08-26 신설

주입과 **함께** 정상 변형을 만들어 `rc=0` 을 확인한다. 정상 변형이란 게이트가 겨누는 위반이 **아니면서** 같은 표면을 건드리는 변경이다.

**대조는 1건이 아니라 배터리다 (2026-08-31 개정).** 게이트가 재는 대상의 **구조 클래스**를 덮는 정상 변형 묶음으로 구성한다. 범위 밖 축은 배터리의 **한 원소일 수는 있으나 배터리를 대신하지 않는다.**

> 구 문면은 *"소유 spec 이 명시적으로 범위 밖이라고 선언한 축을 고르는 것이 가장 좋다"* 였다. **그 권고가 2026-08-31 하루에 세 번 실패했으므로 교체한다** (§왜 배터리인가).

> 절차: 정상 변형 주입 → `rc=0` 확인 → 원복 → `rc=0` 확인. 변형 명령과 출력을 `result.md` 에 박제하고 `RULE-04` notes 에 `control: M/M pass` 를 `injection` 토큰과 나란히 적는다.

- 정상 변형을 구성할 수 없으면 **그 사실과 이유를 `result.md` 에 박제**한다 (`control: n/a (<사유>)`). 조용히 생략하지 않는다.
- 대조가 `rc≠0` 이면 게이트가 **과잉 특정**된 것이다. 게이트를 좁혀서 통과시키고, 좁힐 수 없으면 `50.blocked/task/` 로 격리한다. 정상 변형 쪽을 바꿔 맞추지 않는다.

#### 왜 배터리인가 (2026-08-31 실측)

**범위 밖 축은 두 번 실패한다.**

1. **in-scope 사각지대를 못 본다.** 범위 밖 축은 정의상 이 계약이 **겪지 않을** 변경이다. 거기서 특이도를 재면 "상관없는 변경에 오탐하지 않는다" 만 확인된다.
2. **경계가 움직이면 무너진다.** 대조로 고른 축이 나중에 범위 안으로 들어오면 그 대조는 대조이기를 그만둔다. 실측 2건 — `a13de9a` 는 표 태그가 허용되자 sanitize 대조를 `<table>` → `<iframe>` 으로 옮겨야 했고, `markdown-pipe-table` 은 `colspan` 이 열리는 날 Ctrl-2 를 다시 골라야 한다.

**그렇다고 "in-scope 정상 변경 1건을 넣어라" 로는 부족하다.** `TSK-20260831-16` 의 Dir-1 은 **정확히 in-scope 태그 추가**였고(`'section'`), 그럼에도 결함이 남았다. 빠진 것은 축이 아니라 **구조 클래스**였다 — 프로브에 쓴 태그가 전부 **단독 파싱에서 살아남는** 부류였고, `<td>` 처럼 단독 파싱에서 파괴되는 부류가 배터리에 없었다. 그래서 다음 task 가 표 태그를 더하자 도출이 **무판정으로 붕괴**했다.

**클래스를 세는 법**: 게이트의 판별자가 대상을 어떻게 다루는지 보고, 그 처리에서 **다르게 행동할 수 있는 부류**를 열거한다. 위 사례라면 "단독 파싱 생존" vs "단독 파싱 파괴" 다. 열거가 불가능하면 그 사실을 `result.md` 에 박제한다.

**주입도 같은 함정을 갖는다.** 같은 게이트가 수리된 뒤에도 뚫렸다 — 정책을 호출부에 인라인하고 **주석 처리된 옛 상수를 남기면** 도출이 주석 속 배열에 걸려 개수 1을 얻고 `rc=0` 을 낸다. 실효 정책이 무측정으로 늘어나는데 17/17 초록이다. `injection: 3/3` 의 민감도가 **"파일에 배열 리터럴이 정확히 하나"** 라는 우연에 의존하고 있었다.

> **텍스트를 읽는 게이트는 텍스트의 우연에 기댄다.** 위 사례의 해법은 실측으로 확인됐다 — 소스 텍스트를 읽지 않고 **동작으로 실효 정책을 복원**하는 프로브가 네 변형 전부에 면역이었다 (`alive=27/27` · `dead=13/13`). `RULE-06 §관측 표면` 이 이미 같은 것을 말하고 있다.

> **왜 필요한가** — 주입은 **민감도**(위반을 잡는가)만 재고 `grep dry-run` 은 **특이도**(정상 상태에서 오탐하지 않는가)를 현 HEAD 한 점에서만 잰다. 둘 다 **정상 변형에서 오탐하는가** 는 재지 않는다. 실측 2건: (1) `react-query-test-queryclient-single-source.test.ts` 가 헬퍼를 `\(\)` 로 못 박아 인자 추가라는 정당한 변경을 깨뜨렸다 — 소유 spec 이 인스턴스 갯수 정책을 범위 밖으로 명시했는데도 그랬다. (2) `check:coverage-attribution` 이 측정 창 중의 트리 변경을 `등급 4 (완전성 붕괴)` 로 오보해, 존재하지 않는 결함을 carve 후보로 올렸다. **두 결함 모두 주입 왕복을 `N/N detect` 로 통과했다.**

> `grep dry-run` 은 **특이도**(정상 상태에서 오탐하지 않음)만 검증하고, 주입은 **민감도**(위반을 실제로 잡음)를 검증한다. 둘은 독립이다. 민감도 0 인 게이트도 정상 트리에서는 기대 hit 수와 정확히 일치해 dry-run·Phase 1 재실행·developer 검증을 전부 `rc=0` 으로 통과한다. 2026-08-24 실측 — 그렇게 통과한 검출력 0 게이트가 5건이었고, 그중 `check-deps-coherence.sh` 는 `npm ls` 의 `UNMET DEPENDENCY` 라인을 설치된 것으로 계수해 **잡으라는 drift 만 구조적으로 못 보는** 상태였다.

## 계약을 뒤집는 task (2026-08-31 신설)

기존 동작을 **바꾸는** task 는 그 동작을 박제한 기존 단언과 필연적으로 충돌한다.
task 문면이 "기존 단언 교체 금지" 를 무차별로 걸면 세 요구가 동시에 성립하지 않는다:

1. 계약을 구현하라
2. 그 계약이 뒤집는 명제를 박제한 단언은 건드리지 마라
3. 스위트를 `rc=0` 으로 만들어라

> **실측 (2026-08-31, `TSK-20260831-15`)** — task 가 세 곳(`:51`·`:68`·`:111`)에서 "교체 금지 — 가산만" 을 지시했다. 파서 변경 후 기존 단언 **5건**이 붉었고 5건 전부 같은 명제(*"들여쓰지 않은 줄은 목록을 끊고 문단이 된다"*)를 박제하고 있었다 — **같은 task 의 §배경 이 결함으로 선언한 산출 그 자체**다. 소유 spec 은 이 상황을 이미 예고하고 있었다 (`markdown-list-item-content-start.md:76` — *"기대 문자열은 바뀌지만 입력은 그대로다"*). **그 문장이 task 문면으로 전파되지 않은 것이 직접 원인이다.**

### (T1) 충돌 단언은 발행 시점에 열거한다 — planner 의무

동작을 바꾸는 task 는 `## 테스트` 에 **옛 명제를 박제한 단언 목록과 갱신 후 기대값**을 박제한다.

planner 는 이미 격리 사본에서 baseline 을 실측한다. **같은 사본에서 변경을 모사해 스위트를 한 번 돌리면 이 목록이 발행 전에 드러난다.** 열거할 수 없으면 그 사실을 박제한다 — "교체 금지" 로 대신하지 않는다.

### (T2) "교체 금지" 는 지목된 대조 게이트에만 건다

보호 대상은 **DoD 가 이름으로 지목한 대조 게이트**다. 그 밖의 단언에 무차별로 거는 것은 보호가 아니라 완료 불능이다. 지금 문면은 **보호 대상과 부수 피해를 구분하지 않는다.**

### (T3) 갱신이 불가피할 때의 규약 — developer
