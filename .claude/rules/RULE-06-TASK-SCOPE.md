# RULE-06 Task 스코프 & 게이트

작업지시서 `## 검증/DoD` 에 grep 형태 게이트가 1건 이상이면 **`## 스코프 규칙` 섹션 필수**.

## 섹션 스펙
```markdown
## 스코프 규칙
- **expansion**: 허용 | 불허 | N/A
- **grep-baseline**:
  - `grep -rn "<pattern>" <path>` → N hits in M files:
    - `src/foo.js:12`
- **rationale**: <1~2줄>
```

- **허용**: baseline 밖 파일도 게이트 충족 목적으로 정상화 가능.
- **불허**: scope 밖 변경 금지. 위반 파일이 scope 밖이면 developer 는 `50.blocked/task/` 격리.
- **N/A**: grep 게이트 없음.

**planner / inspector** 는 작성 시점에 baseline 을 **실제 실행해** 박제한다. **developer** 는 수행 전 `expansion` 을 읽고 따른다.

## 게이트 실효 검증

게이트를 **신설·수정하는 task** 는 아래를 DoD 로 명기한다. 일반 task 에는 적용하지 않는다.

- **주입**: spec 이 선언한 검출 방향마다 위반 1건을 넣어 `rc≠0` → 원복 → `rc=0`. `RULE-04` notes 에 `injection: N/N detect`.
- **음성 대조**: 게이트가 겨누는 위반이 **아니면서** 같은 표면을 건드리는 정상 변형에서 `rc=0`. `control: M/M pass` 를 나란히. 구성 불가면 `control: n/a (<사유>)` — 조용히 생략하지 않는다.
- 대조가 `rc≠0` 이면 게이트가 **과잉 특정**된 것이다. 게이트를 좁힌다. **정상 변형 쪽을 바꿔 맞추지 않는다.**

**주입·대조 명령과 그 출력(rc + 게이트가 낸 수치)을 `result.md` 에 박제한다.** rc 만으로는 "주입이 안 들어갔다 / 판정 창 밖에 떨어졌다 / 게이트가 무감하다" 가 구별되지 않는다.

> **왜 필요한가** — 주입은 민감도만, dry-run 은 현 HEAD 한 점의 특이도만 잰다. 둘 다 통과하고도 검출력이 0 인 게이트가 이 저장소에서 반복 관측됐다.

## 게이트를 쓸 때 겪은 것

규칙이 아니라 **실측된 함정**이다. 새 게이트를 만들 때 훑어보고, 해당 없으면 넘어간다.

- **`rc=2` 는 "위반 없음" 이 아니다.** 대상을 못 열었다는 뜻이다. 0 을 기대하는 게이트에서 `rc=1` 과 구별해야 한다.
- **0 을 기대하는 게이트는 매치될 입력을 넣어 rc 가 뒤집히는지 한 번 확인한다.** 패턴이 어떤 입력에도 매치 못 하면 영원히 초록이다.
- **주석이 게이트를 충족시킨다.** 소스 텍스트를 세는 게이트는 주석의 낱말도 센다 — 문서를 잘 달수록 검출이 죽고, 안티패턴을 문서화하면 CI 가 깨진다. **가능하면 텍스트가 아니라 동작으로 실효 상태를 재라.**
- **계수 게이트의 검출 방향은 앵커 유무가 정한다.** 줄 앵커가 있으면 제거·추가 양쪽을 잡고, 없으면 한쪽만 잡는다.
- **추출 실패 검출** — 추출은 조용히 실패한다. 빈 추출에 `bash -c ""` 는 `rc=0` 이다. `awk -v` 는 이스케이프를 해석한다. 추출 후 **비어 있지 않음을 단언하고 문자열을 출력에 박제**한 뒤 실행한다. spec 본문의 명령은 손으로 옮겨 적지 말고 파일에서 추출한다.
- **인자 없는 `grep` 은 stdin 을 먹는다** — 검증 루프의 명령 목록 자체를 삼킨다.
- `grep -E` 의 `\|` 는 리터럴 파이프이고 BRE 에서는 교대다. **`sed -E` 는 `\b` 를 지원하지 않는다.** 대화형 zsh 에서 `grep` 이 가로채이므로 `bash -c` 로 감싼다.
- **측정 대상 목록은 열거하지 말고 `find`/glob 으로 도출한다.** 하드코딩은 나중에 추가된 것을 스캔 밖에 숨긴다. 도출 결과가 공집합이면 무판정 실패로 처리한다.
- **게이트는 production 이 소비하는 표면을 잰다.** 단위 격리 import 만으로 등록·연결을 단정하지 않는다.
- **격리 사본에는 `.git` 도 gitignored 경로도 없다.** git·큐 상태를 묻는 판정은 저장소 루트에서 한다. `src` 는 심볼릭 링크로 두지 않는다 (BSD `grep -r` 이 따라가지 않아 모집단이 공집합이 된다).

## 계약을 뒤집는 task

동작을 **바꾸는** task 는 그 동작을 박제한 기존 단언과 충돌한다. "기존 단언 교체 금지" 를 무차별로 걸면 구현·보존·녹색 스위트 세 요구가 동시에 성립하지 않는다.

- **planner**: 충돌하는 단언 목록과 갱신 후 기대값을 **발행 시점에 열거**한다. 격리 사본에서 변경을 모사해 스위트를 한 번 돌리면 드러난다. "교체 금지" 는 **DoD 가 이름으로 지목한 대조 게이트에만** 건다.
- **developer**: 갱신할 때 **입력은 바꾸지 않고 기대값만** 갱신한다. 그 단언이 지키던 직교 명제는 **가산으로 보존**한다. 지목된 대조 게이트는 건드리지 않는다 — 건드려야 한다면 계약이 잘못된 것이므로 격리한다. 무엇을 왜 갱신했는지 `result.md` 에 박제한다.
