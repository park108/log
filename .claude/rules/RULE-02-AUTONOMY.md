# RULE-02 독립 실행 & 공통 금지

## 원칙
- **무상태**: 컨텍스트는 파일시스템만.
- **큐 기반**: 에이전트 간 직접 호출 금지. `specs/**` 생성/이동만.
- **No-op**: 입력 큐 비면 무해 종료.
- **비대화**: 사용자 질문·승인 요청 금지. 모호하면 `blocked/`.
- **Fail-fast**: 실패·충돌 → `blocked/` + `{slug}_reason.md`. 재시도 없음.
- **멱등**: 같은 입력 2회 = 같은 결과.

## 금지
- 자기 writer 영역 밖 생성/수정/삭제 (RULE-01 매트릭스).
- 다른 에이전트 큐 파일 내용 수정.
- `rm -rf`, `git reset --hard`, `git clean -f`, `git checkout -- .`, `git push --force*`, `git config`, `--no-verify`, `git commit --amend`.
- 삭제 필요 시 `mv` 로 대체.

> **이 목록은 트리로 범위가 나뉘지 않는다 (2026-08-28 명문화).** 저장소 밖 임시 경로·scratchpad·격리 클론에서도 동일하게 금지다. 2026-08-28 하루에 `rm -rf`·`rm -f -r` 자진 신고가 4건 있었고 전부 scratchpad 정리였다 — 무해한 사용이 맞다. 그럼에도 예외를 두지 않는 이유는 **판정이 "지금 어디에 있는가" 에 의존하게 되기 때문**이다. 파괴는 정확히 그 믿음이 틀렸을 때 일어나며, 그 순간 cwd 를 오인한 에이전트는 자기가 예외 안에 있다고 믿는다. 브라이트 라인은 판단을 없애려고 있는 것이므로 판단을 되살리는 예외를 두지 않는다.
>
> 정리는 `mkdir -p <tmp>/trash && mv <대상> <tmp>/trash/` 로 한다. 임시 경로는 세션 종료와 함께 회수되므로 잔존은 문제가 아니다. **이 절을 근거로 자진 신고를 반복하지 않아도 된다** — 규약은 이미 이 사안을 판정했다.
- **자기가 만들지 않은 워킹트리 변경의 원복** (§교차 작업 파괴). 경로를 지목한 `git checkout <path>` · `git restore <path>` · 백업 덮어쓰기도 포함한다 — 위 금지 목록의 `git checkout -- .` 류만 피하면 되는 것이 아니다.
- **메인 워킹트리에서의 프로토타이핑.** 실험은 저장소 밖 임시 경로에서 한다. `git worktree` 를 쓰더라도 산출이 메인 트리에 새지 않는지 확인한다.
- **예외**: `RULE-03 §정체 감지` 가 정한 lock 자가 생성(`.claude/locks/**`)·`50.blocked/pipeline/` 쓰기·`.claude/reports/<agent>.ndjson` append 는 자기 writer 영역으로 간주한다. **lock 삭제는 운영자 전용.**

### 교차 작업 파괴 (2026-08-24 관측 · 2026-08-26 명문화)

> planner 가 `git worktree` 프로토타이핑 산출을 메인 트리에 흘렸고, 이를 "즉시 원복" 하면서 자기가 만들지 않은 developer 의 **미커밋 작업을 blind revert** 했다. developer 는 `git checkout`·`reset`·`clean` 을 한 번도 실행하지 않았는데 `nothing to commit, working tree clean` 을 만나 이를 감지했다. 복구된 것은 순전히 운이었다 — 주입 절차의 부산물로 `cp -p` 백업이 남아 있었다.

- 워킹트리 원복은 **자기가 이 세션에서 만든 변경에 한정**한다. 그 밖은 원복 대상이 아니라 **다른 writer 의 작업**이다.
- 파괴가 의심되면 **추가 조치 없이 즉시 중단**하고 `50.blocked/pipeline/` 에 박제한다. 되살리려는 시도가 2차 파괴가 된다.
- **파괴 창과 겹친 측정은 무효다.** 그 구간의 `rc` 는 존재하지 않는 트리의 rc 이며 `RULE-07 §promote 조건 2` · `RULE-06 §게이트 실효 검증` 의 증거로 쓸 수 없다. 재측정 전까지 그 수치를 보고에 박제하지 않는다.

> 실제 피해가 더 컸던 쪽은 파일이 아니라 **측정 귀속**이었다. developer 는 파괴 창이 `npm test`·`build`·`check:*` 구간과 겹쳤다는 이유로 1차 검증 라운드 전체를 폐기해야 했다.

## 커밋 / 푸시
- 세션 시작: 자기 영역 밖 staged 항목은 `git reset HEAD -- <path>` 로 언스테이지.
- **큐 진행 1단위마다 커밋한다** (§단위 커밋). 단위가 1개뿐이면 결과적으로 단일 커밋이다. `git add` 는 파일 명시. 스테이지 비면 생략.
- 민감 파일 (.env, *.pem, 자격증명) 금지.
- **subject ≤ 72자.** tick 카운터·체인 수치·소인수분해 서사 금지 — 상세는 body 로. (`.husky/commit-msg` 강제)
- 메시지: `{scope}({agent}): {요약}` — `{scope}` ∈ {spec, req, task, followup}. developer task 커밋은 `{type}: {task title}` — `{type}` ∈ {feat, fix, refactor, chore, test, docs}.
- **운영자 커밋은 `operator: {요약}`** (agent 괄호 없음). 에이전트는 이 형식을 쓰지 않는다. 범위는 `rules/` · `.claude/agents/` · `.gitignore` 등 `check-commit-writer-coherence` 가 `meta` 로 분류하는 경로에 한정하며, **`meta` 경로와 에이전트 소유 경로(`src/**` · `specs/**` · `scripts/**`)를 한 커밋에 섞지 않는다** — 섞으면 어떤 단일 writer 도 생성할 수 없는 커밋이 되어 cross-writer 판정에 걸린다 (2026-08-24 실제 발생).
- **push 는 developer 전용**. 그 외는 로컬 커밋까지.
- 훅 실패는 원인 수정·재시도. 우회 금지.

### 경로 지정 커밋 (2026-08-31 신설)

**커밋은 인덱스가 아니라 경로로 한다.** `git add` 후 `git commit` 대신 `git commit -- <paths>` 를 쓴다. 커밋 직후 아래를 확인한다:

```
git show --name-only --format='' HEAD
```

**자기 writer 영역 밖 경로가 한 줄이라도 있으면 즉시 중단하고 `50.blocked/pipeline/` 에 박제한다.** `--amend`·`reset` 으로 되돌리지 않는다 (§금지 · §교차 작업 파괴).

> **계기 (2026-08-31 실측)** — `.husky/pre-commit` 의 `lint-staged` 는 미스테이지 변경을 **stash 했다가 되돌린다.** 그 왕복 중에 다른 writer 가 스테이지해 둔 `specs/**` 편집 3건이 developer 의 `src` 커밋(`86ede5c`)에 함께 담겼다. **소실은 없었고** developer 가 자진 신고한 뒤 경로 지정 커밋으로 전환해 재발이 0 이다. 그 날 writer 경계를 넘은 커밋은 이 한 건뿐이다.

### 워크트리 분리는 답이 아니다

에이전트마다 `git worktree` 를 주자는 제안이 나올 수 있다. **이 파이프라인에서는 불가능하다.**

큐 전체가 gitignored 다 (`specs/10.followups` · `20.req` · `40.task` · `60.done` — `.gitignore:28-33`). gitignore 된 파일은 새 워크트리에 존재하지 않으므로, **분리하는 순간 에이전트들이 서로의 큐를 볼 수 없다.** 파이프라인의 조정 매체가 바로 그 공유 트리다.

프로토타이핑·주입 왕복은 **저장소 밖 격리 사본**(`git archive HEAD | tar -x -C <tmp>` + `node_modules` 심볼릭 링크)에서 한다 — 이쪽은 이미 §금지 가 요구하고 있고 실제로 잘 작동한다. 공유가 필요한 것은 커밋과 큐뿐이므로, 남는 위험은 **인덱스 공유**이고 그것은 경로 지정 커밋으로 닫힌다.

### 단위 커밋 (2026-08-26 신설)

> **계기**: inspector 가 4연속으로 산출 0 을 냈다 (watchdog 2 · 절전 2). 네 세션 모두 실질 분석을 수행했고 모두 **커밋 직전에** 죽었다. 구 문면("세션 종료 직전 … 단일 커밋")은 세션을 all-or-nothing 으로 만들어, 재시도가 누적되지 않고 매번 0 에서 다시 시작하게 했다.

**커밋 단위는 세션이 아니라 큐 진행 1단위다.** 1단위 = 큐 경계 `mv` 1건 + 그 이동이 요구한 자기 영역 편집. 단위가 끝나면 **다음 단위로 넘어가기 전에** 커밋한다.

- 단위가 끝나지 않았으면 커밋하지 않는다. 부분 편집 상태는 커밋 대상이 아니다.
- `mv` 없이 자기 영역 편집만 발생한 tick (drift 동기화·마커 재배치 등) 은 그 편집 전체가 1단위다.
- **no-op tick 은 여전히 커밋하지 않는다.** 스테이지가 비면 생략한다 — 빈 커밋 금지는 그대로다.
- 커밋 수가 늘어도 `RULE-04` 보고는 tick 당 1회다. ndjson 1줄·stdout 블록 1개는 불변이며, `moved` 는 그 tick 의 전 단위를 합산한다.

> 이 규칙이 겨냥하는 것은 커밋 빈도가 아니라 **손실 단위**다. 세션이 죽는 시점은 고를 수 없지만, 죽었을 때 무엇이 남는지는 고를 수 있다.
